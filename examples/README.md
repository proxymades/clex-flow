# Примеры проектов

Импортируйте файл `.clex.json` кнопкой «Импортировать проект» на главном экране CLEX Flow.

## Умный светильник

Три проекта работают вместе через один MQTT-брокер:

| Проект | Назначение |
| --- | --- |
| [Пульт ESP32-P4 Nano](smart-lamp-controller-p4.clex.json) | Распознаёт шесть голосовых команд и воспроизводит подтверждение после ответа исполнителей. |
| [Левый ESP32-S3-ETH](smart-lamp-left-s3-eth.clex.json) | Управляет левым светильником через MOSFET. |
| [Правый ESP32-S3-ETH](smart-lamp-right-s3-eth.clex.json) | Управляет правым светильником через MOSFET. |

Проекты светильников используют блок «Выбор по значению» версии 2.0.0. Для них нужна сборка CLEX Flow с поддержкой этой версии блока.

Все три платы подключаются по Wi-Fi. В каждом проекте замените `YOUR_WIFI` и `YOUR_WIFI_PASSWORD`, адрес `broker.example.com` и значения `YOUR_MQTT_USER` / `YOUR_MQTT_PASSWORD` настройками своей сети и брокера. В примерах выбраны TLS, порт 8883 и проверка сертификата через встроенный набор корневых сертификатов. Выберите параметры, которые поддерживает ваш брокер. MQTT Client ID у трёх проектов разные.

### Голосовой пульт

Используется готовая фраза активации «Привет ESP» и команды:

- «Включи левый светильник»;
- «Выключи левый светильник»;
- «Включи правый светильник»;
- «Выключи правый светильник»;
- «Включи свет»;
- «Выключи свет».

В настройках голосового управления запишите примеры произношения команд, подготовьте модель, затем соберите и запишите прошивку. Подробный порядок приведён в [руководстве голосового управления](../docs/voice.md).

Для индивидуального управления пульт отправляет `ON` или `OFF`, для общего – `GROUP ON` или `GROUP OFF`. После индивидуальной команды звуковое подтверждение запускается напрямую от ответа исполнителя. Для общей команды один синхронизатор ожидает ответы обеих плат в течение 10 секунд и запускает подтверждение один раз. Если один ответ не получен, подтверждение выполнения не звучит. В пример встроен короткий синтетический сигнал; его можно заменить своей записью в блоке воспроизведения.

### Исполнители

На каждой ESP32-S3-ETH подключите GPIO17 (физический контакт 34) к IN1 MOSFET-модуля, GND (контакт 33) к GND модуля. Выбран один канал с активным уровнем HIGH; при запуске прошивки он выключен. Питание нагрузки подключается к силовым клеммам модуля. Требования к модулю и напряжению описаны в [руководстве MOSFET](../docs/mosfet.md).

Один блок «MQTT – Получить» подписан на индивидуальную и общую темы. «Выбор по значению» разбирает текст сообщения:

| Текст команды | Действие | Подтверждение |
| --- | --- | --- |
| `ON` | Включить светильник | Индивидуальное |
| `OFF` | Выключить светильник | Индивидуальное |
| `GROUP ON` | Включить светильник | Общее |
| `GROUP OFF` | Выключить светильник | Общее |

Индивидуальная и общая ветви управляют одним каналом MOSFET. В каждой ветви MQTT-ответ запускается от события «Команда выполнена» и содержит исходный текст команды. Другие значения не включают нагрузку и не запускают ответ. Подтверждение означает выполнение команды GPIO; отдельного датчика состояния нагрузки в примере нет.

Все топики имеют префикс `clex/examples/smart-lamp/`:

| Топик команды | Топик подтверждения |
| --- | --- |
| `left-lamp/set` | `left-lamp/ack` |
| `right-lamp/set` | `right-lamp/ack` |
| `lamps/set` | Левый: `lamps/ack1`; правый: `lamps/ack2` |

Если брокер использует собственный префикс или разрешения на топики, замените его во всех трёх проектах согласованно. Команды и ответы отправляются с QoS 1 и без Retain.

Пример рассчитан на последовательные команды. Синхронизатор различает входы событий, но не номера сетевых запросов: запоздалый ответ от предыдущей общей команды может быть засчитан в новом ожидании. Подробнее о поведении блока: [синхронизация событий](../docs/synchronization.md).
