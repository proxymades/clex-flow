# Модули аппаратной библиотеки

В библиотеке есть аппаратные модули версии 1.0.0: светодиод, кнопка, SPI- и DSI-дисплеи, Ethernet, динамик и камера. Они описаны отдельными JSON в `src/catalog/modules/`, SVG лежат в `src/catalog/assets/`. Проект хранит ссылку и параметры, а не копию реализации.

## Манифест

| Поле | Назначение |
| --- | --- |
| `id`, `version` | Стабильный ID, точная SemVer-версия |
| `kind` | `hardware` или `logic` |
| `name`, `description`, `category`, `categoryName` | Название, описание и категория библиотеки |
| `icon`, `color` | Иконка Lucide и цвет; незнакомая иконка получает общий значок |
| `visual` | Имя SVG, ширина и высота карточки |
| `terminals` | Физические контакты с ID, подписью, типом и координатами на карточке |
| `parameters` | Тип, значение по умолчанию, диапазон/варианты и подпись |
| `constraints` | Цифровое напряжение и правила компонента |
| `compatibility` | Версия формата проекта 3, целевой MCU и версия ESP-IDF либо `platforms[platform]` для другого генератора |
| `hardwareInterface` | Семейство и тип встроенного интерфейса; экземпляр выбирает `interfaceId` |
| `network` | Семейство сетевого интерфейса; экземпляр выбирает `providerId` |
| `display` | Возможности экрана, контроллер, интерфейс и ключ драйвера |
| `firmware` | Ключ фиксированной реализации и зависимости ESP-IDF; `status: "implemented"` |
| `inputs`, `outputs` | У аппаратных модулей пусты; у логических задают типизированные порты |

Типы физических контактов в MVP: `gpio-output` (выход платы на нагрузку), `gpio-input` (вход платы), `ground` (общая земля), `power` (питание с проверкой напряжения). Редактор выбирает направление из типа контакта и проверяет `capabilities` выбранного GPIO. Для дисплеев реализованы SPI и MIPI-DSI. DSI/CSI/I2S и управляющая I2C задаются встроенным профилем интерфейса платы; они не создают произвольные сигнальные провода. I2C-дисплеи, параллельные и аналоговые интерфейсы пока не реализованы.

Параметры поддерживают числа с диапазоном и списки вариантов. Новые JSON/SVG этого контракта автоматически входят во встроенный каталог при запуске Vite или пересборке приложения; менять основной редактор не требуется. Пользовательского установщика/импорта модулей во время работы ещё нет. Новые реализации требуют проверки источников, схемы и тестов.

## Светодиод

Два контакта: анод через резистор на цифровой выход, катод на GND. Резистор – обязательная физическая часть этого модуля, нарисован на карточке и задаётся параметром `resistorOhms` (по умолчанию 330 Ом, 220-100000 Ом). `forwardVoltage` задаёт предполагаемое падение напряжения LED (по умолчанию 2 В, 1.6-3.2 В).

Расчет `(board.logicVoltage - forwardVoltage) / resistorOhms` (ESP32: 3.3 В, Nano: 5 В) – ориентир для выбранных параметров. Предел 8 мА – консервативная политика модуля MVP, не заявленный производителем ток GPIO и не измерение устройства. Проверка не определяет фактический резистор, полярность или маркировку светодиода.

## Кнопка

Нормально разомкнутая кнопка между цифровым входом и GND. Параметры: внутренняя подтяжка вверх и антидребезг 5-1000 мс (по умолчанию 30 мс). У четырёхконтактной тактовой кнопки перед подключением нужно определить пары по её документации: изображение модуля показывает электрический контакт, а не универсальную распиновку корпуса.

Генератор включает внутреннюю подтяжку вверх и периодически фильтрует состояние через заданный debounce. «Чтение GPIO» возвращает электрический уровень: отпущенная кнопка true, нажатая false. Работа конкретной кнопки пока не проверена аппаратно.

## Версии и прошивка

При назначении контактов проверяются наличие модуля, точная версия экземпляра, целевой формат, поддерживаемая цель (ESP32-S3 или ESP32-P4) и версия ESP-IDF платы. Неизвестные/несовместимые модули показываются как ошибка без подмены версии. Такую схему можно сохранить, но назначать контакты отсутствующему модулю нельзя.

`firmware.generatorKey` выбирает фиксированную реализацию в `firmware/generator.js`. Генератор проверяет зарегистрированные реализации и версию 1.0.0; неизвестный ключ блокирует сборку. Таймер исполняется в сгенерированной прошивке через esp_timer и очередь FreeRTOS. Дисплеи используют отдельный реестр драйверов платформ: ST7789/SPI и JD9365/DSI. Ethernet реализован для W5500/SPI и IP101/RMII. ES8311/I2S и OV5647/CSI используют отдельные медиа-задачи; точные зависимости и настройки задает `firmware/runtime-profiles.json`. Пользовательские исполняемые расширения еще не реализованы. JSON не содержит shell-команд и произвольного исполняемого кода.

## Логические модули

Логические модули `clex.logic.*` версии 1.0.0 включают таймер, счетчик, GPIO, Serial, экран, Ethernet, проверку HTTP/HTTPS, звуковой сигнал и захват кадра. Их контракт, порты, параметры и ограничения описаны в [logic.md](logic.md). Все определения находятся в тех же JSON-каталогах, разделяются полем `kind`, используют общий редактор карточек и точные версии проектов. Компиляция и аппаратная проверка учитываются отдельно: физическая работа подтверждена пользователем для S3-ETH/ST7789 и сети; новые драйверы P4 требуют проверки устройства.

## Дисплейные модули

Поле `display` описывает возможности экрана отдельно от `terminals` и подключения. `controllerId` ссылается на каталог контроллеров, `driverKey` – на реализацию выбранной платформы. Несколько модулей могут использовать один драйвер с разными размерами, сигналами и инициализацией. Общий логический модуль `clex.logic.display` выбирает любой экземпляр аппаратного модуля с полем `display`; его `editor: "screen"` открывает единый редактор. Подробнее: [дисплеи](displays.md).

Для Arduino AVR поддержка задается `compatibility.targets: ["atmega328p"]` и `compatibility.platforms: {"arduino-avr": "1.8.6"}` дополнительно к существующим полям ESP-IDF. Совместимость в интерфейсе и проверках проекта определяется одним `moduleSupportsBoard`. Генератор AVR использует фиксированный набор реализаций Arduino Core; зависимости ESP-IDF из общих описаний модулей в AVR-проект не переносятся.

## Программный компонент MQTT

`clex.hardware.mqtt` имеет `softwareInterface: "mqtt"` и пустой список `terminals`. Его параметры задают сеть, брокер и протокол. Блоки `clex.logic.mqtt-control`, `clex.logic.mqtt-send` и `clex.logic.mqtt-receive` используют обычный `componentId` и типизированные порты графа. Совместимость проверяется по существующей сетевой реализации платы. [Описание MQTT](mqtt.md).
