# Модули аппаратной библиотеки

В библиотеке есть аппаратные модули версии 1.0.0: светодиод, кнопка и TFT-дисплей. Они описаны отдельными JSON в `src/catalog/modules/`, SVG лежат в `src/catalog/assets/`. Проект хранит ссылку и параметры, а не копию реализации.

## Манифест

| Поле | Назначение |
| --- | --- |
| `id`, `version` | Стабильный ID, точная SemVer-версия |
| `kind` | `hardware` или `logic` |
| `name`, `description`, `category`, `categoryName` | Название, описание и категория библиотеки |
| `icon`, `color` | Иконка Lucide и цвет; незнакомая иконка получает общий значок |
| `visual` | Имя SVG, ширина и высота карточки |
| `terminals` | Физические контакты с ID, подписью, типом и координатами на карточке |
| `parameters` | Тип, значение по умолчанию, диапазон/варианты и подпись |
| `constraints` | Цифровое напряжение и правила компонента |
| `compatibility` | Версия формата проекта 3, целевой MCU и ESP-IDF |
| `firmware` | Ключ фиксированной реализации и зависимости ESP-IDF; `status: "implemented"` |
| `inputs`, `outputs` | У аппаратных модулей пусты; у логических задают типизированные порты |

Типы физических контактов в MVP: `gpio-output` (выход платы на нагрузку), `gpio-input` (вход платы), `ground` (общая земля), `power` (питание с проверкой напряжения). Редактор выбирает направление из типа контакта и проверяет `capabilities` выбранного GPIO. Для дисплея реализован SPI; I2C, параллельные и аналоговые интерфейсы пока не реализованы.

Параметры поддерживают числа с диапазоном и списки вариантов. Новые JSON/SVG этого контракта автоматически входят во встроенный каталог при запуске Vite или пересборке приложения; менять основной редактор не требуется. Пользовательского установщика/импорта модулей во время работы ещё нет. Новые реализации требуют проверки источников, схемы и тестов.

## Светодиод

Два контакта: анод через резистор на цифровой выход, катод на GND. Резистор – обязательная физическая часть этого модуля, нарисован на карточке и задаётся параметром `resistorOhms` (по умолчанию 330 Ом, 220-100000 Ом). `forwardVoltage` задаёт предполагаемое падение напряжения LED (по умолчанию 2 В, 1.6-3.2 В).

Расчёт `(3.3 - forwardVoltage) / resistorOhms` – ориентир для выбранных параметров. Предел 8 мА – консервативная политика модуля MVP, не заявленный производителем ток GPIO и не измерение устройства. Проверка не определяет фактический резистор, полярность или маркировку светодиода.

## Кнопка

Нормально разомкнутая кнопка между цифровым входом и GND. Параметры: внутренняя подтяжка вверх и антидребезг 5-1000 мс (по умолчанию 30 мс). У четырёхконтактной тактовой кнопки перед подключением нужно определить пары по её документации: изображение модуля показывает электрический контакт, а не универсальную распиновку корпуса.

Генератор включает внутреннюю подтяжку вверх и периодически фильтрует состояние через заданный debounce. «Чтение GPIO» возвращает электрический уровень: отпущенная кнопка true, нажатая false. Работа конкретной кнопки пока не проверена аппаратно.

## Версии и прошивка

При назначении контактов проверяются наличие модуля, точная версия экземпляра, целевой формат, ESP32-S3 и версия ESP-IDF платы. Неизвестные/несовместимые модули показываются как ошибка без подмены версии. Такую схему можно сохранить, но назначать контакты отсутствующему модулю нельзя.

`firmware.generatorKey` выбирает фиксированную реализацию в `firmware/generator.js`. Генератор проверяет зарегистрированные реализации и версию 1.0.0; неизвестный ключ блокирует сборку. Таймер исполняется в сгенерированной прошивке через esp_timer и очередь FreeRTOS. Дисплеи используют отдельный реестр драйверов платформ; первый драйвер – ST7789 SPI. Ethernet и пользовательские исполняемые расширения ещё не реализованы. JSON не содержит shell-команд и произвольного исполняемого кода.

## Логические модули этапа 3

Дополнительно включены пять модулей `clex.logic.*` версии 1.0.0. Их контракт, порты, параметры и ограничения описаны в [logic.md](logic.md). Все определения находятся в тех же JSON-каталогах, разделяются полем `kind`, используют общий редактор карточек и точные версии проектов. Реализации генератора добавлены на этапе 4 и проверены реальной компиляцией ESP-IDF.

## Дисплейные модули

Поле `display` описывает возможности экрана отдельно от `terminals` и подключения. `controllerId` ссылается на каталог контроллеров, `driverKey` – на реализацию выбранной платформы. Несколько модулей могут использовать один драйвер с разными размерами, сигналами и инициализацией. Общий логический модуль `clex.logic.display` выбирает любой экземпляр аппаратного модуля с полем `display`; его `editor: "screen"` открывает единый редактор. Подробнее: [дисплеи](displays.md).
