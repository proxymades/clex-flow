# Доступность устройств ESP-NOW

ESP-NOW передает кадры без постоянного соединения. Запуск местного радио, наличие MAC в списке устройств и успешная отправка кадра не означают, что приложение на другой плате отвечает. См. [описание ESP-NOW Espressif](https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/api-reference/network/esp_now.html).

## Настройка

Добавьте **Управление ESP-NOW**, выберите действие **Следить за устройством** и удаленное устройство из настроек монтажа. В каждой прошивке должен быть настроен MAC второй платы и согласованы канал и шифрование. Для автоматической проверки обе платы должны использовать прошивку с поддержкой проверки доступности. На отвечающей плате добавлять отдельный блок проверки не требуется.

По умолчанию проверка отправляется раз в 1000 мс, таймаут связи составляет 5000 мс. Это настраиваемые параметры приложения. Таймаут должен быть не меньше трех периодов проверки. Для спящих устройств подберите интервалы под их режим работы.

Проверка использует отдельные запросы и ответы с одноразовым идентификатором. Они не вызывают обработчики обычных сообщений или команд, не меняют режим Normal/LR и не увеличивают счетчики сообщений. Эти же запросы используются для [измерения потерь](#измерение-потерь). Для зашифрованного устройства проверяется HMAC. Успешные ответы обычного обмена также подтверждают доступность платы.

## Выходы

| Выход | Значение |
| --- | --- |
| Состояние связи | 0 – ожидание первого ответа; 1 – связь есть; 2 – нет ответа; 3 – местное радио не готово |
| Устройство на связи? | Есть ответ, возраст которого меньше таймаута |
| Уровень сигнала, дБм | RSSI последнего актуального ответа этого устройства; 0 при отсутствии измерения |
| RSSI актуален? | Есть измерение RSSI и связь не устарела |
| Уровень сигнала, текст | Число либо `--`, если измерения нет или истек таймаут |
| Секунд после ответа | Возраст последнего ответа; -1 до первого ответа |
| Данные устройства обновлены | Событие изменения значений, включая истечение таймаута |
| Связь появилась / потеряна | События перехода доступности выбранной платы |

Для индикатора связи подключите **Состояние связи** и используйте готовые состояния источника. Для текстового RSSI подключите **Уровень сигнала, текст**. Событие обновления можно подключить к отдельным входам **Обновить** этих элементов либо воспользоваться помощником подключения данных.

У нескольких плат независимые состояния. Добавьте отдельный блок наблюдения для каждого нужного устройства. Несколько блоков для одного MAC разделяют проверочные запросы, но могут иметь разные таймауты и связи в графе; используется минимальный заданный период проверки.

## Потеря связи и сохраненные данные

| Данные | После истечения таймаута |
| --- | --- |
| Доступность выбранного устройства | Нет ответа, логический выход – Нет |
| Текущий RSSI устройства | Неактуален; числовой выход – 0, текстовый – `--` |
| Возраст ответа | Продолжает расти |
| Готовность местного радио, MAC, Normal/LR | Сохраняют собственное состояние |
| Счетчики сообщений и обменов без ACK | Сохраняют накопленные значения |
| Последнее принятое сообщение и RSSI в блоке приема | Остаются историей последнего пакета |
| GPIO и исполнительные действия | Изменяются только по заданной логике, например от события потери связи |

Нулевой числовой RSSI обозначает отсутствие актуального измерения, а не физический уровень сигнала. Для показа предпочтительнее текст `--` вместе с индикатором связи.

**Радио готово?** в действии **Следить за состоянием** относится к местной плате. **RSSI последнего пакета** в блоке **Получено ESP-NOW** относится к конкретному событию приема. Эти выходы не заменяют наблюдение за доступностью выбранного устройства.

После восстановления ответов состояние и RSSI обновляются автоматически. Проверка доступности не подтверждает выполнение команды: для этого по-прежнему используется отдельное подтверждение результата команды.

## Измерение потерь

Действие **Следить за устройством** автоматически измеряет доставку нумерованных проверочных пакетов **от этой платы к выбранному устройству**. Приемник возвращает накопленное число уникальных пакетов, поэтому потерянный обратный отчет не считается потерей прямой передачи: следующий отчет уточняет результат. Для измерения на обеих платах нужна обновленная прошивка. Отдельный блок на отвечающей плате не требуется.

| Выход | Значение |
| --- | --- |
| Пакетов в измерении | Количество отправленных проверочных пакетов до номера из последнего отчета |
| Получено проверочных пакетов | Сколько уникальных пакетов из этого измерения учел приемник |
| Потеряно проверочных пакетов | Разница между двумя предыдущими значениями на момент отчета |
| Потери, % | Потеряно / пакетов в измерении × 100 |
| Статистика актуальна? | Есть отчет с ненулевым количеством пакетов, возраст которого меньше таймаута связи |
| Статистика потерь, текст | Например, `Получено 95 из 100` и `Потери 5 (5,0%)` на двух строках; до первого измерения `--`, после таймаута `Нет свежего отчета` |
| Еще не сверено пакетов | Пакеты после последнего отчета. Их доставка неизвестна; они еще не включены в потери |
| Ошибки отправки проверок | Запросы, которые местный драйвер не принял к отправке; не включены в число переданных пакетов |

Подключите **Статистика потерь, текст** к динамическому тексту дисплея или Serial, а **Данные устройства обновлены** – к событию обновления. Для собственных числовых индикаторов используйте выходы счетчиков вместе с **Статистика актуальна?**. При потере связи числовые выходы сохраняют последний сверенный результат, а текст явно сообщает, что свежего отчета нет. Потери последних пакетов можно уточнить, когда другая плата снова ответит.

Вход **Сбросить измерение потерь** начинает новый тест для выбранного устройства. Перед первым учитываемым пакетом выполняется согласование измерения; оно не входит в счетчики. Перезапуск любой платы также начинает новое измерение. Смена Normal/LR сама по себе счетчики не сбрасывает: для сравнения режимов подключите событие **Режим установлен** к **Сбросить измерение потерь**. Несколько наблюдателей одного устройства используют общие счетчики; их таймауты отображения могут различаться.

Измерение относится к доставке проверочных пакетов приложению, а не к каждому физическому радиокадру. Проверки не повторяются логикой CLEX Flow, но внутренние повторы Wi-Fi остаются частью работы радиодрайвера. Дубликаты учитываются один раз; перестановка пакетов обрабатывается в окне 256 номеров. Пакет, отставший на 256 номеров или больше, уже не входит в полученные. При периоде 1000 мс окно соответствует примерно 256 секундам. До нового отчета пропуск может быть предварительным: поздно пришедший пакет в пределах окна уточняет следующий результат.

Для сравнения Normal и Long Range используйте одинаковый период и сопоставимое число пакетов. Наблюдение с двух сторон дает два независимых направления; это не вычитание общих TX и RX одной платы. Счетчик **Без подтверждения** продолжает описывать результат обычных обменов с повторами и не заменяет измерение потерь.
