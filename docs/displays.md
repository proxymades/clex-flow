# Дисплеи и редактор экранов

Дисплей добавляется как аппаратный компонент в «Монтаже». Блок «Экран дисплея» в «Логике» выбирает этот же экземпляр устройства. Подключения и интерфейс хранятся один раз; несколько блоков могут показывать предпросмотр одного устройства.

Двойное нажатие на блок или кнопка «Открыть редактор экрана» открывают общий редактор. Доступны фон, текст, координаты, перетаскивание, цвет и размеры шрифта 14/20/28 px. «Сохранить интерфейс» переносит изменения в проект; затем проект сохраняется вручную или обычным автосохранением. «Отмена» оставляет предыдущий интерфейс.

## PNG и заставка

Кнопка **Добавить PNG** загружает логотип с прозрачным фоном. Перетаскивайте изображение на холсте, меняйте его размер за нижний правый угол или задавайте ширину/высоту в свойствах. Пропорции сохраняются. Пиксели хранятся внутри JSON проекта; исходный файл рядом с проектом не нужен.

У изображения есть галочка **Заставка при запуске** и поле **Время заставки, сек** (0,1-60 секунд, по умолчанию 3). В редакторе область заставки расположена слева, основной экран – справа. При включении заставки логотип переносится во вторую область. На плате сначала отображается заставка, затем открывается основной экран. Данные основного экрана обновляются и во время заставки. При следующем запуске платы заставка показывается снова. Без галочки изображение остаётся частью основного экрана.

На одном экране используется одна заставка: включение галочки у другого изображения переводит предыдущий логотип в основной экран. Фон общий для обеих областей. Изображения не создают портов данных в «Логике».

PNG обрабатывается при импорте на компьютере. В проекте сохраняются RGBA-пиксели, при генерации прошивки создаётся массив RGB565 с отдельной плоскостью прозрачности (LVGL RGB565A8). Эти ресурсы включаются в `main.c` и обычную контрольную сумму прошивки. Плате не нужны файловая система или PNG-декодер.

Исходный PNG ограничен 8 МБ и 16 млн пикселей; при импорте изображение уменьшается до 65 536 пикселей и стороны не более 512 px. Суммарный отображаемый размер изображений одного экрана ограничен 65 536 пикселями, размер JSON проекта – существующими 2 МБ. При превышении редактор предлагает уменьшить изображения.

Проверки: `node --test tests/images.test.js`, `npm run test:image-ui`. `npm run test:image-runtime` использует уже подготовленную локальную библиотеку LVGL из `.artifacts/lvgl-host` и проверяет цвет, прозрачность, обновление данных во время заставки и переход по таймеру без ESP-IDF и платы.

## Первый модуль

В каталоге реализован TFT-модуль SPI 240×320 на контроллере ST7789, RGB565, с внутренним подключением подсветки. Производитель и маркировка модуля не установлены. Его профиль описывает конкретную конфигурацию; другие модули с тем же контроллером могут требовать другого разрешения, смещений, питания и инициализации.

Для проверочной схемы ESP32-S3-ETH:

| Контакт дисплея | Контакт платы |
| --- | --- |
| VCC | 3V3 |
| GND | GND |
| SCL / SCLK | GPIO16 |
| SDA / MOSI | GPIO17 |
| CS | GPIO18 |
| DC | GPIO15 |
| RES / RST | GPIO38 |

Отдельного BL в этом профиле нет. SPI выбирается из свободных контроллеров платы в «Монтаже», 20 МГц, режим 0, RGB, инверсия включена, смещения нулевые. Для доступности GPIO камеры в проекте нужно подтвердить, что камера отключена. Назначайте именно физические контакты своего модуля, сверив подключение.

Генератор использует `esp_lcd` из ESP-IDF 5.4.4 и LVGL 9.2.2. При первой сборке дисплейной прошивки официальный Component Manager загружает закреплённую зависимость LVGL в отдельный каталог проекта сборки. Установка SDK не изменяется. Статическому экрану не нужен событийный путь от таймера. Первая реализация драйвера поддерживает один активный дисплей; интерфейсы разных экземпляров редактор хранит раздельно.

## Динамические значения

Текстовый элемент имеет стабильный ID и два режима: **Статический текст** и **Динамическое значение**. Для динамического элемента задаются название, тип данных (число, логическое значение или текст), префикс, суффикс и начальное значение. Шрифт, цвет и координаты остаются обычными свойствами элемента. Например, префикс `Температура: ` и суффикс ` °C` дают `Температура: 25 °C`.

В «Логике» соедините выход данных с текстовым элементом или состоянием индикатора. Сигнал обновления подключается автоматически из описания источника; дополнительных ручных соединений для обычной привязки не требуется. Данные и обновление сохраняются как обычные связи и отменяются одним Undo. Если момент обновления уже настроен вручную и подходит источнику, он сохраняется. Через **Подключить данные** можно изменить источник и момент обновления.

После сохранения интерфейса у одного блока «Экран дисплея» появляются вход **Обновить все значения** и отдельные типизированные входы с названиями динамических элементов. Нового блока дисплея для каждого значения не требуется. Для ручного управления можно подключить событие источника к **Обновить все значения** вместо отдельных событий обновления элементов. Для нескольких динамических элементов также доступны события **Обновить: название элемента**: независимые источники могут обновлять каждый свой элемент в том же блоке. Общий **Обновить все значения** обновляет все значения и доступен через **Дополнительные контакты**; при наличии связи он всегда виден. Отсутствующий или несовместимый источник останавливает сборку с сообщением.

Начальное значение показывается в предпросмотре и на устройстве до первого события обновления. Предпросмотр редактора не выполняет граф и не получает данные с устройства. Для логических значений используются подписи «Да» и «Нет».

Привязки находятся в обычных `logic.edges`; `targetHandle` совпадает с ID элемента, а устройство определяется `parameters.componentId`. Переименование, перемещение и оформление элемента сохраняют связи. Смена его типа удаляет несовместимую связь данных; удаление или перевод последнего динамического элемента в статический режим также убирает ненужные событийные входы обновления.

Генератор создаёт реестр текстовых объектов LVGL по ID устройства и элемента. Событие обновляет только соответствующие метки через `lv_label_set_text_fmt`; повторное значение пропускается. События таймера попадают в существующую очередь. Действия графа, обновления меток и `lv_timer_handler()` выполняются последовательно в `flow_worker`. DMA-обработчик сообщает только о завершении передачи, через разрешённый LVGL вызов `lv_display_flush_ready()`.

### Таймер и счётчик

Блок **Счётчик** является обычным источником числовых данных. Название входа учитывает шаг: **Прибавить 1**, **Прибавить 5** или **Вычесть 2**. По этому входу он изменяет число на заданный шаг, по входу **Вернуть начальное число** возвращается к начальному значению. **Текущее число** выдаёт число, **Счетчик обновлен** запускает потребителей. Диапазон – знаковое 32-битное целое; на границе значение остаётся на пределе. Отрицательный шаг уменьшает счётчик. Выход можно подключить также к числовому входу блока «Сообщение в монитор».

Готовый проект: [динамический счётчик](../examples/dynamic-counter.clex.json). Импортируйте JSON через «Открыть JSON», проверьте подключение по таблице выше, выберите совместимую ESP-IDF и порт платы.

Схема первого теста:

1. **Таймер:** 1000 мс, **Сработал → Счетчик / Прибавить 1**.
2. **Счетчик:** начало 0, шаг 1; **Счетчик обновлен → Экран дисплея / Обновить: Счётчик**.
3. **Счетчик / Текущее число → Экран дисплея / Число: Счётчик**.
4. В редакторе текст «Счётчик»: динамический режим, тип **Число**, префикс `Счётчик: `.
5. Сохраните проект, соберите и запишите прошивку. Счётчик изменяется один раз в секунду.

## Unicode и шрифты

Текст сохраняется как Unicode в UTF-8 JSON и передаётся LVGL в UTF-8. В предпросмотре используется тот же Montserrat Medium, из которого официальным `lv_font_conv` созданы шрифты прошивки. Включены доступные глифы Basic Latin и Cyrillic, включая русские буквы и «Ё/ё», и символ градуса «°»: 317 глифов на размер, 4 bpp. Полный Unicode в прошивку не включается. Неиспользуемые размеры шрифта удаляются линкером из итогового образа.

Тестовая надпись: «Привет, мир! CLEX Flow». Символы, которых нет в выбранном наборе, показываются как ошибка до сборки. Предпросмотр браузера и LVGL используют разные растеризаторы; предпросмотр показывает композицию и поддерживаемые символы, но не обещает идентичность каждого пикселя.

Наборы символов описаны в `src/displays/fonts/character-sets.json`. Другой язык добавляется соответствующим набором и шрифтом с нужными глифами, затем шрифты преобразуются официальным конвертером:

```sh
npm install --prefix .artifacts/font-converter --ignore-scripts --no-audit --no-fund lv_font_conv@1.5.3
node scripts/generate-display-fonts.mjs
```

Конвертер нужен разработчику для подготовки ресурсов; приложение и SDK Manager не требуют его установки. Generated C хранится в `lvgl-fonts.json` и используется одинаково фронтендом и нативной подготовкой сборки. Лицензии исходного шрифта и LVGL сохранены рядом с ресурсами.

## Расширение каталога

- Контроллер описывается в `src/catalog/controllers/`; модель модуля – отдельным JSON в `src/catalog/modules/` с полем `display` и собственными `terminals`.
- `display` содержит модель, контроллер, интерфейс, разрешение, цветовые форматы, инициализацию, платформы, `driverKey` и графические возможности. Редактор читает эти возможности, а не названия моделей или плат.
- Плата описывает целевую платформу, MCU, питание и доступные аппаратные интерфейсы. Текущий генератор реализован для ESP32-S3 и ESP32-P4; другие платформы требуют отдельной реализации генератора/драйверов.
- Драйвер выбирается по платформе и ключу. Сейчас реализованы `esp-idf/st7789-spi` и `esp-idf/jd9365-dsi`; аппаратная инициализация отделена от общего создания объектов LVGL.
- Новый модуль с реализованным драйвером добавляется JSON/SVG без изменения редактора экрана. Новый контроллер требует своего драйвера и регистрации; графический редактор остаётся общим.

I2C, параллельные дисплеи, OLED, страницы, картинки и интерактивные элементы пока не реализованы.

Проверена реальная компиляция статического экрана с кириллицей. Пользователь подтвердил запись прошивки на Waveshare ESP32-S3-ETH и работу физического TFT-дисплея ST7789.

Источники: [официальный пример ESP-IDF](https://github.com/espressif/esp-idf/blob/v5.4.4/examples/peripherals/lcd/spi_lcd_touch/main/spi_lcd_touch_example_main.c), [LVGL 9.2.2](https://components.espressif.com/components/lvgl/lvgl/versions/9.2.2), [конвертер шрифтов LVGL](https://github.com/lvgl/lv_font_conv).

## Локальная проверка LVGL

`tests/dynamic-lvgl-runtime.mjs` выполняет сгенерированные функции с настоящей LVGL 9.2.2 и шрифтами прошивки на компьютере. Он проверяет значения, сброс, границы счётчика, сохранение статического текста, изменённые пиксели и частичную отрисовку. Для запуска требуется исходный код этой версии LVGL из локального Component Manager и собранная нативная библиотека; SDK не устанавливается. Такая проверка дополняет проверку на плате.

Настройте `CLEX_TEST_LVGL_PATH` на каталог LVGL. Создайте `.artifacts/lvgl-host/lv_conf.h` с `#define LV_COLOR_DEPTH 16`, `#define LV_MEM_SIZE (256 * 1024U)` и `#define LV_USE_OS LV_OS_NONE`, затем выполните:

```sh
cmake -S "$CLEX_TEST_LVGL_PATH" -B .artifacts/lvgl-host \
  -DLV_CONF_PATH="$PWD/.artifacts/lvgl-host/lv_conf.h" \
  -DLV_CONF_BUILD_DISABLE_EXAMPLES=ON -DLV_CONF_BUILD_DISABLE_DEMOS=ON \
  -DLV_CONF_BUILD_DISABLE_THORVG_INTERNAL=ON
cmake --build .artifacts/lvgl-host --target lvgl
npm run test:dynamic-runtime
```

Требуется Clang с UndefinedBehaviorSanitizer. Проверка UI: `npm run test:dynamic-display-ui`, с работающим веб-предпросмотром и Chromium.

Документация LVGL: [потоки и прерывания](https://docs.lvgl.io/9.2/porting/os.html), [обновление меток](https://docs.lvgl.io/9.2/widgets/label.html).

## Индикаторы состояния

«Добавить индикатор» создаёт общий элемент LVGL: скруглённый фон, надпись и необязательная цветная точка. Настройте размеры, радиус, отступы, расстояние до точки, её размер и сторону, выравнивание и шрифт. Перетаскивайте элемент или меняйте размеры за нижний правый угол; точные значения доступны в свойствах.

Каждое состояние имеет своё название, значение, надпись, цвет фона, текста и точки. Состояния пользователь задаёт самостоятельно. В статическом режиме выберите одно состояние. В динамическом режиме задайте тип входа, начальное значение и резервное состояние для значений, отсутствующих в списке. Сопоставление значений точное; логические ключи – Да/Нет, числовые и текстовые ключи задаются в свойствах.

После сохранения соедините выход данных с входом состояния индикатора, а событие готовности – с соответствующим входом «Обновить состояние: название индикатора». Для произвольной строки включите «Надпись из логики»: появится отдельный текстовый вход. Эта надпись заменяет текст выбранного состояния, сохраняя его оформление. Состояние и надпись можно обновлять от независимых источников в одном блоке дисплея. Все связи сохраняются вместе с обычным графом проекта.

Редактор показывает начальное состояние. Выбор состояния в свойствах позволяет просмотреть его оформление перед сохранением. Обновления на устройстве меняют существующие объекты LVGL и пропускают повторные значения.

[Пример сетевых индикаторов и аппаратная проверка](network.md). Локальная проверка реальной LVGL: `npm run test:indicator-runtime` с тем же окружением, что и проверка динамического текста.

### Готовые состояния источника

В редакторе индикатора выберите «Состояния источника» и нажмите «Использовать состояния источника». Набор добавит именованные состояния с правильными значениями. Надписи и цвета можно настроить обычным способом; числовые коды находятся в дополнительных настройках состояния. До сохранения интерфейса изменения остаются в редакторе.

В помощнике «Подключить данные» при выборе выхода с описанными состояниями доступен переключатель «Использовать состояния …». Он применяется только после нажатия «Подключить». Отмена оставляет проект прежним; Undo/Redo восстанавливают вместе связи и оформление. Надписи, цвета и дополнительные пользовательские состояния сохраняются для совместимого типа значений.

Расшифровка показана компактным списком в подсказке контакта и его свойствах. Это общий механизм: модуль описывает `valueStates` у выхода – начальное и резервное значения, а также `options` с `value`, `label` и `dotColor`. Поддержаны числовые, логические и текстовые значения. Для непрерывных чисел, например счетчика, набор не придумывается.

## MIPI-DSI на ESP32-P4

Модуль 10.1-DSI-TOUCH-A использует общий редактор с разрешением 800×1280, драйвер JD9365 и сенсор GT9271. Подключение к разъему DSI, управление подсветкой, питание PHY и общая I2C учитываются в профиле платы. Компиляция этого драйвера проверена локально; физическая работа панели и touch на P4 еще не подтверждена. Подробнее: [ESP32-P4-NANO, аудио, камера и проверка ресурсов](esp32-p4-nano.md).
