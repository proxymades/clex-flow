# Сеть и индикаторы состояния

## Подготовленный пример

Импортируйте [network-status.clex.json](../examples/network-status.clex.json) через «Мои проекты». Проект содержит один дисплей, Ethernet, проверку ресурса и два независимых индикатора. Заголовок относится к выбранной плате; IP выводится из Ethernet, начальное значение пустое.

Для TFT используется подтверждённое подключение: питание 3V3 и GND, SCLK GPIO16, MOSI GPIO17, CS GPIO18, DC GPIO15, RST GPIO38; подсветка подключена внутри модуля. Камера отключена. Перед записью проверьте свой монтаж в редакторе.

В примере выбран DHCP и адрес `https://example.com/`. В «Логике» выберите блок «Проверка интернета» и задайте нужный ресурс, метод, интервал и таймаут. URL не должен содержать имя пользователя и пароль. Сейчас реализованы IPv4-сети, включая DNS-имена. Параметры и оформление меняются через редактор, исходный C редактировать не требуется.

## Аппаратный интерфейс

В «Монтаже» добавьте «Ethernet» и выберите интерфейс из описания платы. Сейчас реализован встроенный W5500 на Waveshare ESP32-S3-ETH. Его аппаратные сигналы находятся в профиле платы: SCLK13, MOSI11, MISO12, CS14, INT10, RST9. Контакты проложены на плате и не требуют ручных проводов в редакторе.

SPI-контроллер выбирает пользователь из свободных интерфейсов платы. Ethernet и дисплею можно назначить SPI2 и SPI3 в любом порядке. Чтобы поменять их местами, сначала установите одному устройству «Не выбран», затем переназначьте оба. Сборка проверяет конфликт контроллеров и GPIO. Общая модель интерфейса отделена от реализации драйвера; для другой платы нужен документированный профиль и реализованный аппаратный драйвер.

Выберите DHCP либо статический IPv4. Для статического адреса задайте IP, непрерывную маску, шлюз в той же подсети и, при необходимости, DNS. Адрес устройства должен быть свободным в вашей сети.

## Логические блоки и привязки

«Ethernet» ссылается на аппаратный экземпляр и выдаёт Link, наличие IP, состояние, действительные IP/маску/шлюз/DNS и ошибку. События: «Данные сети обновлены», «Соединение установлено», «Соединение потеряно», «IP-адрес обновлен». Подключение означает физический Link; получение IP – отдельное изменение.

| Значение состояния Ethernet | Значение |
| --- | --- |
| 0 | Link отсутствует |
| 1 | Link есть, ожидание IP |
| 2 | IP получен |
| 3 | Ошибка аппаратной инициализации |

«Проверка интернета» использует активный сетевой маршрут ESP-IDF. Реализация проверки отделена от драйвера Ethernet. Другие аппаратные сетевые драйверы в приложении пока не реализованы.

| Значение проверки | Значение |
| --- | --- |
| 0 | Ожидание сетевого маршрута с IP |
| 1 | Выполняется проверка |
| 2 | Получен HTTP-ответ 200-299 |
| 3 | Ресурс недоступен, ошибка или таймаут |

Выходы: логический результат, состояние, время ответа в миллисекундах, код HTTP и ошибка. Время включает DNS, соединение, TLS при HTTPS и получение заголовков; `-1` означает отсутствие измерения. При ожидании или новой проверке результат – Нет, поэтому для различения ожидания и ошибки используйте выход состояния.

HEAD запрашивает заголовки. GET также завершает проверку после получения заголовков, без загрузки всего тела. Используйте конечный URL: автоматические переходы по перенаправлениям не выполняются. Если сервер не поддерживает HEAD, выберите GET. Успех относится к выбранному ресурсу. Интервал задаёт минимальное время между началами проверок; несколько блоков обслуживаются последовательно одной фоновой задачей. Потеря маршрута отменяет актуальность незавершённых результатов; после восстановления выполняется новая проверка.

Создайте состояния и подписи индикатора в редакторе. Для Ethernet соедините «Состояние подключения» с входом состояния индикатора и «Данные сети обновлены» с его входом показа. Для проверки ресурса используйте «Этап проверки» и «Данные проверки обновлены». Помощник «Подключить данные» создаст эти связи автоматически. Для IP соедините «IP-адрес устройства» с текстовым элементом: обновление подключится автоматически. Произвольная надпись индикатора подключается через текстовый вход после включения «Надпись из логики».

## Сборка и аппаратная проверка

Сохраните проект, выберите установленную ESP-IDF 5.4.4, соберите прошивку и загрузите актуальную сборку через штатную панель приложения. Откройте монитор 115200 бод. Сообщения `CLEX_ETH` показывают действительные сетевые параметры, `CLEX_HTTP` – результат, код ответа, время и ошибку. Сравните их с дисплеем.

1. При сохранённом питании отключите Ethernet-кабель: индикатор Ethernet показывает отсутствие Link, IP очищается, проверка ресурса переходит в ожидание.
2. Подключите кабель к сети с DHCP: проверьте переход Link → ожидание IP → действительный IP. Ожидание IP может быть коротким. Сверьте адрес с DHCP-клиентами роутера.
3. При полученном IP задайте недоступный ресурс, например имя в зарезервированной зоне `.invalid`: Ethernet остаётся подключённым, проверка завершается ошибкой DNS.
4. Верните доступный HTTP/HTTPS-ресурс с ответом 200-299: проверьте положительный результат, код HTTP и время ответа.
5. Повторите отключение/подключение: прежний успешный результат не должен оставаться после потери сети. Для проверки Link без IP используйте тестовую сеть без DHCP, сохранив в проекте DHCP.
6. При необходимости повторите со свободным статическим адресом своей сети и с обменом SPI2/SPI3 между устройствами.

При питании только от PoE отключение кабеля выключает плату. Для проверки потери Link питание должно сохраняться через подключение, допустимое документацией производителя. Проверка выключения от PoE проводится отдельно.

## Выполнение и ресурсы

Сетевые обработчики передают копии снимков состояния через существующую очередь графа. LVGL обновляется только в задаче логики, вместе с `lv_timer_handler`; сетевые задачи не обращаются к объектам дисплея. DNS и HTTP имеют ограниченный таймаут, HTTP-клиент освобождается после каждой попытки, поздние ответы устаревшего маршрута отбрасываются. Повторный Link не создаёт новый драйвер Ethernet. При ошибке инициализации освобождаются уже созданные ресурсы.

Генератор включает штатные компоненты ESP-IDF и фиксированную таблицу разделов с приложением до 3 МиБ для поддерживаемых профилей платы. Зависимость LVGL остаётся закреплена на 9.2.2.

Источники: [Ethernet ESP-IDF 5.4.4](https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/api-reference/network/esp_eth.html), [HTTP Client](https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/api-reference/protocols/esp_http_client.html), [Waveshare ESP32-S3-ETH](https://docs.waveshare.com/ESP32-S3-ETH).


## Отображение последнего результата

Чтобы очередной фоновый запрос не менял надпись на «Проверка», соедините «Проверка завершена» с отдельным событием обновления индикатора вместо «Данные проверки обновлены». Выход данных «Этап проверки» остаётся подключён к тому же элементу. До первого результата индикатор показывает своё начальное состояние.

Для немедленного сброса индикации при потере действительного IP подключите событие Ethernet «IP-адрес обновлен» к общему входу «Обновить все значения» блока дисплея. Оно обновляет все связанные элементы, в том числе состояние проверки, сбрасываемое в ожидание при смене маршрута. Используйте свободный вход: каждый событийный вход принимает одну связь.

Таймаут относится ко всему запросу, включая DNS и соединение. Транспорт получает оставшийся бюджет соединения; короткие интервалы чтения используются после подключения. Сообщения диагностики различают таймаут соединения, ожидание заголовков, DNS, TLS и смену маршрута. `HTTP: 0` и время `-1` соответствуют отсутствию результата текущей проверки.

`npm run test:network-runtime` запускает сгенерированную функцию на компьютере с моделью транспортных ответов: медленное TCP-соединение, таймаут соединения/заголовков, смена маршрута и освобождение клиента. Требуется Clang; эта проверка дополняет аппаратную.
