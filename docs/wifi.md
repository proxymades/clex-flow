# Wi-Fi

Компонент «Wi-Fi» подключает плату к существующей сети в режиме Station. MQTT и проверка HTTP/HTTPS используют это подключение. Автоматическое подключение работает без логического блока.

Поддерживаются ESP32 DevKit V1 с WROOM-32, ESP32-S3-DevKitC-1, ESP32-S3-ETH и ESP32-P4 Nano. На P4 Nano используется ESP32-C6 через ESP-Hosted и штатные линии SDIO из профиля платы. Требуется совместимая прошивка сопроцессора C6. Для текущего профиля Arduino Nano компонент недоступен: Wi-Fi-драйвер для него не реализован.

## Настройка

1. Добавьте «Wi-Fi» в «Монтаж».
2. Укажите точное название сети и пароль. SSID занимает 1-32 байта UTF-8, пароль – 8-63 байта; пустой пароль означает открытую сеть.
3. Оставьте DHCP либо задайте статические IP, маску, шлюз и DNS. При пустом DNS в статическом режиме используется адрес шлюза.
4. Настройте подключение при запуске, автоматическое восстановление, интервал повторов и таймаут.
5. В компоненте MQTT выберите созданное Wi-Fi-подключение.

Имя сети и пароль сохраняются в JSON-проекте и генерируемой прошивке. Пароль в редакторе скрыт и показывается отдельным переключателем.

Для раздачи с iPhone включите Wi-Fi, «Разрешать другим» и «Максимальная совместимость» в настройках режима модема. Для раздачи на других устройствах выберите сеть 2,4 ГГц с совместимой защитой.

Плата использует один Wi-Fi-контроллер. Компонент «Wi-Fi», «Wi-Fi маршрутизатор» и текущая реализация ESP-NOW не могут управлять им одновременно. Существующие проекты с маршрутизатором продолжают использовать свои настройки. Для перехода на обычное подключение перенесите SSID и пароль в «Wi-Fi» и выберите его в MQTT.

## Логика и диагностика

Блок «Wi-Fi» позволяет подключиться, отключиться, переподключиться и обновить состояние. Ручное отключение приостанавливает автоматические попытки до команды подключения.

Доступны события обновления, подключения, потери соединения, изменения IP и ошибки. Соединение считается готовым после получения IP. Выходы передают состояние, IP, маску, шлюз, DNS, код причины и текст ошибки. После потери соединения адреса очищаются.

| Код | Состояние |
| --- | --- |
| 0 | Отключено |
| 1 | Подключение |
| 2 | Ожидание IP |
| 3 | IP получен |
| 4 | Ошибка |

В Serial сообщения `CLEX_WIFI` показывают результат запуска, полученный IP и числовую причину отказа, например `201 (NO_AP_FOUND)`. Пароль не выводится. Одна попытка подключения завершается событием драйвера или таймаутом; повторное подключение ожидает заданный интервал.

## Проверки

```sh
npm test
npm run test:firmware-parity
npm run test:wifi-builds
```

Последняя команда требует активированной ESP-IDF 5.4.4. Она компилирует сгенерированные проекты с Wi-Fi и MQTT для ESP32, ESP32-S3 и ESP32-P4; платы не прошиваются. Проверки C-логики выполняются на компьютере и не заменяют проверку радиосвязи на устройстве.
