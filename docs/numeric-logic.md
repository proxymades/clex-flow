# Преобразование и сравнение чисел

В категории «Данные» доступны блоки **«Текст в число»** и **«Сравнение числа»**. Они работают с MQTT, датчиками, счётчиками и другими источниками. Поддерживаются ESP32, ESP32-S3, ESP32-P4 и Arduino Nano ATmega328P. Наличие MQTT или дисплея определяется возможностями выбранной платы.

## Текст в число

Соедините исходный текст со входом «Исходный текст», а событие получения данных – со входом «Преобразовать». Изменение текста без события не запускает преобразование.

Формат «Только число» принимает, например, `-10000`, `12.5`, `12,5` и `-1.2e4`. Десятичный разделитель выбирается в настройках. Пробелы по краям разрешены, разделители тысяч не поддерживаются.

Для сообщения `590.0 Па` выберите «Число с подписью» и укажите «Текст после числа»: `Па`. Для `P=12.5 kPa` задайте текст перед числом `P=` и текст после числа `kPa`. Подпись проверяется точно; единицы не пересчитываются. `1 кПа` не превращается автоматически в `1000 Па`.

Выход «Преобразование завершено» срабатывает после каждой попытки. «Число получено» – только после успешной. При ошибке число сбрасывается в NaN, «Число корректно?» становится «Нет», выдаются событие и описание ошибки. Пустые сообщения, лишние символы, NaN, бесконечность и переполнение не принимаются. Числовая часть ограничена 79 байтами, исходный текст – 8192 байтами.

На ESP32 используется double; на Arduino AVR – точность float, примерно 6-7 значащих цифр. Эти ограничения следует учитывать при выборе дробных порогов.

## Сравнение числа

На вход «Проверяемое число» поступают данные, на вход «Проверить» – событие, когда их нужно проверить. Число можно брать непосредственно у датчика; для текстового MQTT Payload сначала нужно преобразование.

В режиме «Сравнение с числом» доступны меньше, меньше или равно, равно, не равно, больше или равно и больше. Значение задаётся в настройках либо поступает на вход «Число для сравнения». Для равенства и неравенства настраивается абсолютный допуск: при допуске 0 сравнение точное.

В режиме «Диапазон» задаются нижняя и верхняя границы. Каждую границу можно включить или исключить. По умолчанию обе включены. Границы могут поступать от других блоков; подключённый вход заменяет соответствующую настройку. Нижняя граница не должна превышать верхнюю. Диапазон из одного числа допустим только при включённых границах.

Блок выдаёт события и значения «Ниже диапазона?», «В диапазоне?» и «Выше диапазона?». Для корректного числа истинно одно из трёх значений. Событие «Проверка завершена» срабатывает после обновления всех выходов. При некорректном входе или границах все логические выходы становятся «Нет», числовой выход – NaN, выдаётся ошибка.

## Пример: два реле по давлению из MQTT

[Проект для ESP32 DevKit V1 WROOM-32](../examples/mqtt-pressure-relays.clex.json) содержит MQTT-подписку, преобразование текста, диапазон и два блока управления реле. Перед сборкой настройте Wi-Fi, брокер, авторизацию и topic. Питание модуля реле в примере внешнее.

| Давление, Па | Реле 1 | Реле 2 |
| --- | --- | --- |
| Меньше −10000 | Включено | Выключено |
| От −10000 до +10000 включительно | Выключено | Выключено |
| Больше +10000 | Выключено | Включено |

Настройки преобразования: «Число с подписью», текст после числа `Па`. Настройки сравнения: «Диапазон», нижняя граница `-10000`, верхняя `10000`, обе границы включены.

Связи:

| Выход | Вход |
| --- | --- |
| MQTT «Payload» | «Текст в число» → «Исходный текст» |
| MQTT «Получено» | «Текст в число» → «Преобразовать» |
| «Текст в число» → «Число» | «Сравнение числа» → «Проверяемое число» |
| «Текст в число» → «Преобразование завершено» | «Сравнение числа» → «Проверить» |
| «Сравнение числа» → «Ниже диапазона?» | Реле 1 → «Включить?» |
| «Сравнение числа» → «Выше диапазона?» | Реле 2 → «Включить?» |
| «Сравнение числа» → «Проверка завершена» | «Выполнить» у обоих реле |

Оба блока реле используют действие **«Установить состояние»**. Поэтому при каждом сообщении обновляются оба канала, в том числе выключается ранее включённый канал. При ошибке преобразования сравнение также выполняется и задаёт обоим реле выключенное состояние. Для этого используется «Преобразование завершено», а не только событие успешного преобразования.

Отсутствие новых сообщений само по себе не вызывает ошибку преобразования: реле сохраняют состояние до следующей команды. Диапазон не хранит предыдущее состояние и не добавляет гистерезис.
