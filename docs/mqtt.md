# MQTT

MQTT использует существующую сеть платы. Добавьте в «Монтаж» Ethernet или Wi-Fi маршрутизатор, затем компонент «MQTT». В одном проекте можно настроить до восьми независимых подключений в пределах доступной памяти платы; все блоки с одинаковым MQTT-компонентом разделяют одно соединение.

Поддерживаются MQTT 3.1.1 и 5.0 через TCP и TLS на текущих профилях ESP32, ESP32-S3 и ESP32-P4. Подключение не зависит от марки брокера. Адрес задается отдельно от порта, без `mqtt://`, пути и учетных данных. Обычные порты – 1883 и 8883; можно указать другой.

## Подключение

Выберите сеть либо оставьте автоматический выбор существующего подключения. MQTT не создает вторую Wi-Fi-сеть и не запускает остановленный маршрутизатор. Для нескольких MQTT-компонентов можно выбрать разные брокеры или разные Client ID на одном брокере.

Настройки компонента:

- версия протокола, адрес, порт, Client ID, логин и пароль;
- TLS с проверкой доверия и имени сервера: встроенные корневые сертификаты либо собственный CA в PEM;
- Keep Alive и таймаут сетевой операции;
- новая или сохраняемая сессия; для MQTT 5 – срок хранения сессии;
- автоматическое подключение, переподключение и интервал попыток;
- LWT: topic, payload, QoS и Retain; для MQTT 5 – задержка публикации.

Пустой Client ID формируется из идентификатора платы и MQTT-компонента. Для сохраняемой сессии задайте постоянный Client ID явно. Одновременные клиенты одного брокера должны иметь разные ID. Подписки активных блоков восстанавливаются при возвращении соединения, включая новую сессию брокера.

TLS не отключает проверку сертификата при ошибке. Для проверки срока действия нужно установленное системное время: прошивка использует синхронизацию времени SNTP. Для частного CA вставьте PEM корневого сертификата; закрытый ключ сервера не требуется.

Пароль скрыт в интерфейсе, но параметры подключения входят в файл проекта и генерируемую прошивку. Для публикации примера используйте отдельные демонстрационные настройки.

## Три блока

**MQTT – Управление.** Входы подключения и отключения, состояние соединения, события изменения состояния, подключения, отключения и ошибки. Ручное отключение приостанавливает автоматические попытки до команды подключения. При включенном автоподключении блок управления необязателен.

Состояния: `0` – отключено, `1` – подключение, `2` – подключено, `3` – переподключение, `4` – ошибка. Выходы ошибки и кода причины доступны для Serial и экрана.

**MQTT – Отправить.** Публикует по событию. Topic и payload берутся из настроек или подключенных текстовых входов. Настраиваются QoS 0/1/2, Retain, кодировка и свойства MQTT 5: Content Type, Payload Format Indicator, Message Expiry, Response Topic, Correlation Data и User Properties. Результат содержит событие успеха либо ошибки, ID сообщения и код причины. Для QoS 0 успех означает принятие сообщения в локальную очередь, без подтверждения получения брокером. Для QoS 1/2 событие успеха приходит после подтверждения протокола.

**MQTT – Получить.** Список фильтров подписки с отдельным QoS, автоматическая подписка, входы подписки и отписки. При приеме доступны topic, payload, QoS, Retain, ID, свойства MQTT 5 в JSON и событие получения. Есть события результата подписки, отписки и ошибки. Выходы сообщения обновляются до запуска события получения.

Фильтры поддерживают `+`, `#` и общие подписки `$share/group/filter`. Для MQTT 5 доступны No Local, Retain As Published и Retain Handling. Блоки одного подключения могут разделять фильтр: отписка одного блока сохраняет подписку остальных. Для одинакового фильтра параметры MQTT 5 должны совпадать; используется наибольший нужный QoS.

## Данные и ограничения

Topic и фильтр – до 256 байт UTF-8. Payload – до 4096 байт после декодирования. Кодировки `Base64` и `HEX` передают произвольные бинарные данные, включая нулевые байты; текстовые выходы графа используют строки UTF-8 без нулевого байта. Correlation Data задается в Base64. User Properties задаются парами ключ/значение.

На блок приема доступно до 16 фильтров. Клиент хранит до 32 незавершенных входящих обменов QoS 2; превышение лимита закрывает соединение с диагностикой. Общий бюджет динамических сообщений и представлений – 64 КиБ. Каждое подключение дополнительно требует памяти для задачи, двух буферов по 8 КиБ, TLS и очереди публикаций до 16 КиБ. Память очередей ограничена; превышение размера, нехватка памяти, отказ брокера, TLS или переполнение очереди дают диагностику. При нехватке памяти сохраненные значения приема могут быть очищены с событием ошибки, чтобы освободить место для следующих сообщений. Переполнение очереди событий требует сброса соединения и сессии; незавершенные публикации получают ошибку, после восстановления активные подписки создаются заново. MQTT 5 reason code сохраняется, включая отказ публикации QoS 2. Настройки MQTT 5, недоступные в 3.1.1, нужно сбросить перед сменой версии.

## Генерация и проверки

Генератор включает ESP-MQTT 1.1.0 непосредственно в проект прошивки, сохраняя лицензию и описание изменений. Установленный ESP-IDF не изменяется. JavaScript и нативный слой используют один пакет исходников. Сборка и запись на плату выполняются существующим механизмом CLEX Flow.

Проверки без платы:

```sh
npm test
npm run test:firmware-components
npm run test:firmware-parity
CLEX_TEST_IDF_ROOT=/path/to/esp-idf npm run test:mqtt-host
npm run test:mqtt-builds
```

Host-проверки компилируют тот же ESP-MQTT и используют локальный Mosquitto с TCP/TLS. Требуются компилятор C, OpenSSL, исходники ESP-IDF 5.4.4 и локальный Mosquitto; пути можно задать через `CLEX_TEST_MOSQUITTO`, `CLEX_TEST_MOSQUITTO_PASSWD`, `CLEX_TEST_OPENSSL_ROOT` и `CLEX_TEST_OPENSSL`. Дополнительно проверяются сгенерированный runtime, незавершенный обмен QoS 2 при смене сети, восстановление после нехватки памяти и настройка TLS. Эти проверки не прошивают устройство и не заменяют проверку выбранной платы и физической сети.
