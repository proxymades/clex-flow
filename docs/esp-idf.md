# Подключение ESP-IDF 5.4.4

CLEX Flow использует **существующую** ESP-IDF 5.4.4 и Python-окружение с инструментами выбранной платы: ESP32-S3/Xtensa или ESP32-P4/RISC-V. Новая установка выполняется через SDK Manager и официальный EIM в собственный каталог, после подтверждения. Обнаруженные пользовательские SDK не обновляются и не переустанавливаются. Редакторы и просмотр кода доступны без SDK; процессы доступны только в Tauri.

## Пример путей EIM на macOS

```text
SDK:    ~/.espressif-s3/v5.4.4/esp-idf
Python: ~/.espressif/tools/python/v5.4.4/venv/bin/python
```

Путь зависит от выбранного каталога установки. Используйте SDK с установленным компилятором выбранной цели и его Python-окружение. Приведенные пути – пример существующей установки S3; она не заменяется при выборе P4.

## Настройки

При запуске SDK Manager проверяет сохранённый выбор и обнаруживает установки EIM, переменных окружения и стандартных каталогов. Для нестандартной установки укажите корень с `tools/idf.py` и Python существующего окружения. Нажмите «Проверить пути». Можно повторить поиск или выбрать другую обнаруженную установку. Проверяются точная версия SDK, версия `idf.py`, GCC, CMake и Ninja; ошибки показываются без подмены статуса.

`idf_tools.py export --format key-value` используется для получения путей инструментов, без выполнения export.sh в shell. Приложение учитывает constraints-файл стандартной установки или EIM. Нестандартные каталоги инструментов, не описанные этой схемой, пока могут потребовать доработки обнаружения. Для обычных GPIO-прошивок Component Manager выключен. Для графики и периферии P4 он включается с фиксированным манифестом LVGL 9.2.2 и/или драйверов из `src/firmware/runtime-profiles.json`, с отдельным кэшем компонентов в каталоге сборки. Дочерние процессы получают `IDF_SKIP_CHECK_SUBMODULES=1`, `PYTHONDONTWRITEBYTECODE=1`; SDK не модифицируется.

## Сборка

Нужны документированный профиль платы, корректный монтаж и поддерживаемый граф или интерфейс дисплея. Обычная GPIO-схема требует таймер со связанным действием; экран, сеть или медиа используют свои механизмы запуска. Для GPIO генератор создаёт четыре файла: `CMakeLists.txt`, `main/CMakeLists.txt`, `main/main.c`, `sdkconfig.defaults`. Дисплейная прошивка дополнительно содержит фиксированный манифест LVGL и C-файлы ограниченных наборов шрифтов. Файлы доступны в диалоге исходников.

На macOS собственный каталог сборки:

```text
~/Library/Caches/kz.clex.flow/firmware/<source-sha256>-<sdk-root-hash>/
```

Здесь выполняется `idf.py -D IDF_TARGET=<target> build`: `esp32s3` либо `esp32p4` из профиля платы. Проекты пользователя не используются как рабочий каталог. Одинаковая схема переиспользует свой кэш; визуальные координаты не меняют исходник. После успешного процесса проверяются bootloader, partitions, app и flash_args; интерфейс показывает путь к готовому app `.bin`. Это отдельный app-образ, не объединённый образ всей flash.

При загрузке компонентов, например LVGL, журнал показывает полученный объём, общий размер и скорость. Если сервер не сообщает размер, проценты не выводятся. После 15 секунд без новых данных появляется сообщение об ожидании. Прогресс одной загрузки обновляется в той же строке; распаковка и проверка файлов отображаются отдельными этапами. Отсутствие загрузки при повторной сборке может означать использование кэша.

«Остановить» завершает группу дочерних процессов. После остановки можно повторно собрать. Успешный build считается пригодным к записи только в текущем сеансе приложения; после перезапуска повторите сборку. SDK, сторонние проекты и исходники при этом не очищаются.

## Порт, запись и Serial

- macOS: `/dev/cu.*`; Bluetooth и debug-console исключены. Порт и описание получаются через установленный pyserial. Подключите плату и обновите список.
- После успешной сборки выберите порт. «Прошить» показывает модель, путь к бинарнику и подтверждение физического монтажа перед заменой программы.
- Backend повторно проверяет наличие порта, актуальность source SHA/SDK и контрольные суммы файлов сборки. Используется фиксированный esptool `--chip <target> --port <port> --baud 460800 write_flash @flash_args` в собственном build-каталоге; shell не используется.
- Serial только читает данные через pyserial на 115200 бод. «Подключён» означает успешное открытие порта, не проверку платы. DTR/RTS не используются для преднамеренного сброса при открытии; конкретный драйвер/USB-мост пока аппаратно не испытан.
- Остановите монитор перед сборкой/записью. Одна операция одновременно. Во время работы изменения схемы и закрытие приложения блокируются; доступна остановка. Прерывание записи может оставить программу неполной, потребуется повторная прошивка.

Для профилей S3 консоль firmware по умолчанию **USB Serial/JTAG**; для USB-UART bridge выберите **UART0** и пересоберите. На ESP32-P4-NANO доступна консоль **UART0** через USB-C/CH343. Подключите соответствующий разъем платы; S3 резервирует USB GPIO19/20 и UART GPIO43/44, P4 – UART GPIO37/38. Неправильный выбор разъёма может дать пустой монитор. Возможности IDF Monitor GDB, декодирование backtrace, ввод команд и автоподключение не реализованы.

Перед первым Blink проверьте модель/ревизию, монтаж LED с резистором на GPIO17 и соответствующий USB-порт. Драйверы P4 DSI/touch, ES8311 и OV5647 требуют аппаратной проверки. Подключение и ограничения: [ESP32-P4-NANO](esp32-p4-nano.md).

[Официальная установка ESP-IDF 5.4.4](https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/get-started/index.html), [esp_timer](https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/api-reference/system/esp_timer.html), [возможности IDF Monitor](https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/api-guides/tools/idf-monitor.html).

Установка, несколько версий, удаление и платформенные ограничения описаны в [SDK Manager](sdk-manager.md).
