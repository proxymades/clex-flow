# Подключение ESP-IDF 5.4.4

CLEX Flow использует **существующую** ESP-IDF 5.4.4 и Python-окружение с инструментами ESP32-S3. Новая установка выполняется через SDK Manager и официальный EIM в собственный каталог, после подтверждения. Обнаруженные пользовательские SDK не обновляются и не переустанавливаются. Редакторы и просмотр кода доступны без SDK; процессы доступны только в Tauri.

## Пример путей EIM на macOS

```text
SDK:    ~/.espressif-s3/v5.4.4/esp-idf
Python: ~/.espressif/tools/python/v5.4.4/venv/bin/python
```

Путь зависит от выбранного каталога установки. Используйте SDK с установленными инструментами ESP32-S3 и его Python-окружение.

## Настройки

При запуске SDK Manager проверяет сохранённый выбор и обнаруживает установки EIM, переменных окружения и стандартных каталогов. Для нестандартной установки укажите корень с `tools/idf.py` и Python существующего окружения. Нажмите «Проверить пути». Можно повторить поиск или выбрать другую обнаруженную установку. Проверяются точная версия SDK, версия `idf.py`, GCC, CMake и Ninja; ошибки показываются без подмены статуса.

`idf_tools.py export --format key-value` используется для получения путей инструментов, без выполнения export.sh в shell. Приложение учитывает constraints-файл стандартной установки или EIM. Нестандартные каталоги инструментов, не описанные этой схемой, пока могут потребовать доработки обнаружения. Для обычных GPIO-прошивок Component Manager выключен. Для дисплейной прошивки он включается с фиксированным манифестом LVGL 9.2.2 и отдельным кэшем компонентов в каталоге сборки. Дочерние процессы получают `IDF_SKIP_CHECK_SUBMODULES=1`, `PYTHONDONTWRITEBYTECODE=1`; SDK не модифицируется.

## Сборка

Нужны документированный профиль платы, корректный монтаж, таймер со связанным действием или сохранённый интерфейс дисплея. Для GPIO генератор создаёт четыре файла: `CMakeLists.txt`, `main/CMakeLists.txt`, `main/main.c`, `sdkconfig.defaults`. Дисплейная прошивка дополнительно содержит фиксированный манифест LVGL и C-файлы ограниченных наборов шрифтов. Файлы доступны в диалоге исходников.

На macOS собственный каталог сборки:

```text
~/Library/Caches/kz.clex.flow/firmware/<source-sha256>-<sdk-root-hash>/
```

Здесь выполняется `idf.py -D IDF_TARGET=esp32s3 build`. Проекты пользователя не используются как рабочий каталог. Одинаковая схема переиспользует свой кэш; визуальные координаты не меняют исходник. После успешного процесса проверяются bootloader, partitions, app и flash_args; интерфейс показывает путь к готовому app `.bin`. Это отдельный app-образ, не объединённый образ всей flash.

«Остановить» завершает группу дочерних процессов. После остановки можно повторно собрать. Успешный build считается пригодным к записи только в текущем сеансе приложения; после перезапуска повторите сборку. SDK, сторонние проекты и исходники при этом не очищаются.

## Порт, запись и Serial

- macOS: `/dev/cu.*`; Bluetooth и debug-console исключены. Порт и описание получаются через установленный pyserial. Подключите плату и обновите список.
- После успешной сборки выберите порт. «Прошить» показывает модель, путь к бинарнику и подтверждение физического монтажа перед заменой программы.
- Backend повторно проверяет наличие порта, актуальность source SHA/SDK и контрольные суммы файлов сборки. Используется фиксированный esptool `--chip esp32s3 --port <port> --baud 460800 write_flash @flash_args` в собственном build-каталоге; shell не используется.
- Serial только читает данные через pyserial на 115200 бод. «Подключён» означает успешное открытие порта, не проверку платы. DTR/RTS не используются для преднамеренного сброса при открытии; конкретный драйвер/USB-мост пока аппаратно не испытан.
- Остановите монитор перед сборкой/записью. Одна операция одновременно. Во время работы изменения схемы и закрытие приложения блокируются; доступна остановка. Прерывание записи может оставить программу неполной, потребуется повторная прошивка.

Консоль firmware по умолчанию **USB Serial/JTAG**. Для USB-UART bridge выберите **UART0** в настройках и пересоберите. Подключите именно соответствующий разъём платы; генератор резервирует USB GPIO19/20 и UART GPIO43/44. Неправильный выбор разъёма может дать пустой монитор. Возможности IDF Monitor GDB, декодирование backtrace, ввод команд и автоподключение не реализованы.

Перед первым Blink проверьте модель/ревизию, монтаж LED с резистором на GPIO17 и соответствующий USB-порт. Пользователь подтвердил запись прошивки на Waveshare ESP32-S3-ETH и работу дисплея ST7789; проверка Blink выполняется отдельно.
