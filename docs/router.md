# Wi-Fi маршрутизатор

Компонент «Wi-Fi маршрутизатор» настраивается в «Монтаже». Он использует штатные IPv4 forwarding/NAPT, DHCP и Wi-Fi API ESP-IDF 5.4.4. Создание W5500 и IP101/RMII выполняют существующие драйверы Ethernet. Общий контроллер маршрутизации одинаков для всех поддержанных адаптеров.

## Платы и режимы

| Профиль платы | Wi-Fi WAN → SoftAP | Ethernet WAN → SoftAP | Wi-Fi WAN → Ethernet LAN | Резервный WAN |
| --- | --- | --- | --- | --- |
| ESP32 DevKit V1 (30 pin) | Да | Нет описанного Ethernet | Нет описанного Ethernet | Нет второго интерфейса |
| Waveshare ESP32-S3-ETH | Да | W5500 | W5500 | Ethernet и Wi-Fi |
| ESP32-S3-DevKitC-1 v1.1 N8R8 | Да | Нет описанного Ethernet | Нет описанного Ethernet | Нет второго интерфейса |
| Waveshare ESP32-P4-NANO | ESP32-C6 / ESP-Hosted | IP101/RMII | IP101/RMII | Ethernet и Wi-Fi |

Для всех перечисленных режимов реализованы генерация и сборка. На ESP32-S3-ETH проверен режим Ethernet W5500 → Wi-Fi SoftAP: доступ нескольких клиентов в интернет и работа под нагрузкой. Остальные режимы и совместимость прошивки сопроцессора P4 требуют отдельных аппаратных испытаний.

Wi-Fi-возможности описаны в `board.wifi`: адаптер, STA/SoftAP, защита, число клиентов и занятые ресурсы. Ethernet выбирается из `networkInterfaces`. Новая плата с совместимым SDK и сетевыми адаптерами использует тот же контроллер; ее аппаратное описание, инструменты сборки и конфигурацию адаптера нужно добавить и проверить.

ESP32 DevKit V1 с ESP32-WROOM-32 поддерживает Wi-Fi WAN → SoftAP; OTA недоступна в текущей схеме разделов для 4 МБ Flash. Профиля ESP32-CAM в каталоге нет. Arduino Nano маршрутизатор не поддерживает.

P4 использует `espressif/esp_hosted` 2.12.3 и `espressif/esp_wifi_remote` 1.4.2. SDIO-пины берутся из описания платы. Требуется совместимая прошивка ESP32-C6; сборка и прошивка основного P4 не заменяют обновление сопроцессора. На P4 в интерфейсе включена WPA2; WPA3 SoftAP отключена до отдельной проверки C6. Для S3 доступны WPA2, WPA3 и смешанный режим.

## Настройка в CLEX Flow

1. Выберите совместимую плату. Для режима с Ethernet добавьте существующий компонент «Ethernet», настройте его интерфейс и свободный SPI, если используется W5500.
2. Добавьте «Wi-Fi маршрутизатор». Выберите основной WAN, при необходимости резервный WAN и Ethernet-компонент.
3. Для Wi-Fi WAN задайте SSID, пароль и DHCP либо статический IPv4. Пустой пароль допускается для открытого WAN. Ethernet WAN берет исходные IPv4-настройки из выбранного Ethernet-компонента.
4. Выберите LAN: SoftAP либо Ethernet. Задайте адрес шлюза, маску и DHCP-диапазон. Сеть WAN не должна пересекаться с LAN. Для WAN с DHCP конфликт дополнительно обнаруживается на устройстве; маршрутизация в конфликтующую сеть не включается, LAN сохраняется.
5. Для SoftAP задайте SSID, пароль, защиту, канал и число клиентов. SSID допускает до 32 байт UTF-8, а не обязательно 32 символа. Одно радио STA+AP работает на общем канале: после подключения STA канал SoftAP следует внешней точке доступа.
6. Проверьте автоматически созданные уникальные пароли локальной сети и администратора. При публикации проекта удалите рабочие секреты из файла.
7. При необходимости задайте проброс TCP/UDP-портов. Адрес назначения должен принадлежать LAN, внешний порт должен быть уникальным для протокола. Правила применяются при включенном NAT и наличии выбранного WAN. CGNAT вышестоящего провайдера может препятствовать входящим подключениям.
8. Соберите и прошейте проект штатными кнопками CLEX Flow. Ручные изменения C/CMake/sdkconfig не требуются.

Для первого знакомства доступны примеры [Wi-Fi WAN → SoftAP](../examples/router-wifi.clex.json), [W5500 → SoftAP с резервным Wi-Fi](../examples/router-ethernet.clex.json) и [P4/IP101 → SoftAP](../examples/router-p4.clex.json). Перед сборкой заполните собственные пароли и данные WAN; в примерах секреты оставлены пустыми.

Готовый [«Тест роутера ESP32-S3-ETH» с дисплеем и температурой](../examples/router-esp32-s3-eth-test.clex.json) использует W5500 как Ethernet WAN с DHCP и раздает интернет через Wi-Fi `CLEX-ROUTER`. ST7789 показывает состояния WAN, интернета и SoftAP, адреса, число клиентов, время работы и температуру кристалла. События сети также выводятся в Serial.

Скачайте JSON и импортируйте его на экране «Мои проекты». Перед сборкой задайте «Пароль локальной сети» и «Пароль администратора» в компоненте маршрутизатора; пароли в примере пустые. Панель доступна по `http://192.168.50.1/`, имя администратора – `admin`. Если меняете SSID, обновите также статическую подпись SSID в редакторе экрана.

Ethernet использует SPI2, дисплей – SPI3. Подключение ST7789: SCLK → GPIO16, MOSI → GPIO17, CS → GPIO18, DC → GPIO15, RESET → GPIO38, VCC → 3V3, GND → GND. В настройках платы камера отключена; перед подключением сверяйте маркировку и ревизию платы.

## Работа сети

WAN получает адрес через DHCP либо использует статический IPv4, маску, шлюз и DNS. Wi-Fi переподключается автоматически. Параметры Ethernet LAN задаются маршрутизатором; один физический Ethernet-порт не может одновременно быть WAN и LAN.

LAN продолжает работать при потере WAN: SoftAP и DHCP сохраняются. Маршрутизатор выбирает первый доступный WAN с успешной проверкой контрольного HTTP/HTTPS-ресурса. Если ни один ресурс не отвечает, но интерфейс имеет допустимый IPv4, он остается кандидатом для маршрута. Основной WAN восстанавливает приоритет после успешной проверки. При смене WAN или его IP таблица NAT пересоздается, поэтому существующим TCP/UDP-сеансам может потребоваться переподключение.

Проверка интернета выполняет настоящий HTTP HEAD с таймаутом и ожидает ответ 200-399. Она показывает доступность выбранного ресурса, а не гарантирует доступ ко всем адресам интернета. Выберите ресурс, поддерживающий HEAD. Для HTTPS используется штатная проверка сертификата и синхронизация времени SNTP; сразу после включения успешная проверка может потребовать времени для получения часов.

DHCP сообщает клиентам LAN-адрес маршрутизатора как DNS. Локальный прокси обслуживает UDP и TCP DNS и использует вручную заданный DNS либо DNS выбранного WAN. При смене WAN клиентам не нужно менять DNS в своей DHCP-аренде. Если WAN еще не предоставил DNS, используется резервный адрес 1.1.1.1. Обрабатывается по одному DNS-запросу за раз с двухсекундным сетевым таймаутом; размер сообщения ограничен 4096 байтами.

При выключенном NAT сохраняется обычная IPv4-маршрутизация. Вышестоящему маршрутизатору в таком случае нужен обратный маршрут к LAN; NAPT не заменяется фиктивным состоянием интерфейса.

## Визуальная логика

Компонент работает без логических блоков, если включен автоматический запуск. Для событий и данных добавьте блок «Маршрутизатор» и выберите компонент из монтажа.

- Действия: запуск, остановка, включение/выключение SoftAP, переподключение WAN, обновление состояния и клиентов.
- Изменение SSID/пароля: заполните параметры блока либо подключите текстовые входы и подайте сигнал «Применить SSID/пароль SoftAP» или «Применить SSID/пароль WAN». Изменение проверяется, сохраняется в NVS и применяется с перезапуском сетевых служб.
- События: запуск, появление/потеря WAN IPv4, изменение WAN IP, результат проверки интернета, подключение/отключение Wi-Fi-клиента и ошибка.
- Данные: WAN/LAN IP и MAC, шлюз, DNS WAN, активный интерфейс, число и список Wi-Fi-клиентов, время работы и последняя ошибка.

Для дисплея соедините нужный выход с динамическим элементом через обычный помощник «Подключить данные». Событие «Состояние обновлено» доступно как момент обновления. Подключение к Serial выполняется теми же типизированными связями. Учет клиентов использует SDK: MAC, IPv4 из DHCP-аренды и RSSI. Адрес клиента со статическим IPv4 может быть неизвестен DHCP-серверу. Список клиентов Ethernet не подменяется списком Wi-Fi-клиентов.

Операции управления передаются в отдельную задачу. Граф и дисплей обновляются в задаче графа; сетевые callback не вызывают граф напрямую.

## Управление на устройстве

Откройте `http://<LAN-IP>/` из локальной сети и введите имя и пароль администратора, заданные в проекте. Из WAN доступ запрещен. Страница содержит состояние, адреса и клиентов, настройки WAN, SoftAP, LAN, DNS, DHCP и правил портов, переподключение WAN и перезагрузку.

При первом обращении браузер запрашивает учетные данные администратора. Запрос без учетных данных не считается ошибкой входа. Повторные неверные попытки ограничиваются отдельно по IP-адресу клиента; правильные данные принимаются сразу.

Аутентификация HTTP Basic работает только на доверенной LAN; HTTP не обеспечивает шифрование транспортного соединения. Wi-Fi LAN должна использовать защищенный режим. Нельзя считать этот интерфейс HTTPS-панелью или открывать его в интернет через внешний прокси без дополнительной защиты.

Пароли не возвращаются API чтения настроек и не выводятся контроллером в журнал. Пустое поле пароля на странице сохраняет прежнее значение. Чтобы переключить WAN на открытую сеть, можно применить пустой пароль через блок логики либо пересобрать исходную конфигурацию в CLEX Flow. Межсайтовые записи отклоняются; страница не загружает внешние скрипты.

Сохранение и применение выполняются асинхронно. После изменения LAN IP или SSID может потребоваться переподключение клиента. Изменения хранятся в NVS отдельно для компонента проекта и восстанавливаются после отключения питания. Изменение исходной конфигурации компонента в CLEX Flow создает новую базовую конфигурацию и заменяет прежнее переопределение при следующей прошивке; обычное обновление кода с прежними настройками сохраняет локальные изменения.

Выбор физической роли Ethernet WAN/LAN выполняется в CLEX Flow и требует новой сборки. Веб-страница не обещает переключение роли уже созданного netif. Остановка маршрутизатора выключает его сетевые службы и страницу управления; повторный запуск выполняется из логики либо после перезагрузки с включенным автозапуском.

OTA доступна при включенной настройке и наличии двух разделов приложения; текущая схема требует не менее 8 МБ Flash. Загрузите бинарный образ приложения для той же платы. SDK проверяет образ перед выбором нового загрузочного раздела; прерванная загрузка не переключает загрузочный раздел. Пароль администратора также защищает OTA. Это не подпись выпуска и не замена Secure Boot.

## Границы поддержки

- Одновременно управлять тем же радио из ESP-NOW и маршрутизатора пока запрещено валидатором. Прежние проекты ESP-NOW сохраняют свои драйверы и поведение.
- Достоверные общие счетчики RX/TX для всех адаптеров пока не реализованы и не показываются фиктивными значениями.
- WPA3 SoftAP на P4 ограничена возможностями и проверкой конкретной прошивки C6. Размеры буферов, число клиентов и OTA-память также ограничены профилем.
- PPPoE, VLAN, IPv6 routing и VPN не включены.

Маршрутизация использует официальные `esp_netif`, `esp_wifi`, `esp_eth` и lwIP NAPT с существующими драйверами CLEX Flow. Изменение установленного SDK не требуется. Локальная страница управления входит в генерируемую прошивку.

## Проверки

`npm test` проверяет генерацию, сохранение/импорт проекта, конфликты и привязки дисплея. C-тесты выполняют реальный код проверки конфигурации, выбора WAN, аутентификации и DNS UDP/TCP с управляемыми моделями SDK/сокетов. Это проверка программной логики, не передача пакетов через платы.

`npm run test:router-ui` и `npm run test:router-admin-ui` проверяют интерфейсы в изолированном браузере. `npm run test:firmware-parity` сравнивает файлы JavaScript/Rust. `npm run test:router-builds` после активации ESP-IDF 5.4.4 собирает матрицу S3/P4 в `.artifacts/router-build`; отдельный вариант выбирается через `CLEX_ROUTER_CASE`.

На оборудовании необходимо проверить:

1. Получение нескольких DHCP-аренд, адрес шлюза и DNS; UDP/TCP DNS и доступ клиентов наружу через NAT в каждом режиме.
2. Статические WAN/LAN, конфликт динамической WAN-подсети, проброс TCP/UDP и переподключение клиента после смены WAN.
3. Обрыв Ethernet и Wi-Fi, возврат основного WAN, изменение WAN IP/DNS и сохранение LAN при отсутствии интернета.
4. Холодный старт, повторные start/stop, отключение питания после сохранения NVS, изменение настроек из графа и веб-страницы.
5. SoftAP/AP+STA и фактическую совместимость версии C6 на P4, смену общего канала STA/AP, несколько клиентов под нагрузкой.
6. Запрет доступа к панели со стороны WAN, неверный пароль, применение конфигурации, OTA корректного/неверного образа и прерванную загрузку.
7. Совместную работу с дисплеем и другими периферийными компонентами, доступную память и производительность при реальном трафике.
