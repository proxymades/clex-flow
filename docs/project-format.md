# Проект JSON, формат 3

Один UTF-8 JSON-файл на проект, максимум 2 МБ. Валидация структуры отделена от проверки монтажа: незавершённую схему можно сохранить, но её ошибки видны в нижней панели.

```json
{
  "id": "01234567-89ab-4cde-8fab-0123456789ab",
  "name": "Blink Mount",
  "description": "Внешний светодиод",
  "formatVersion": 3,
  "createdAt": "2026-10-09T04:00:00.000Z",
  "updatedAt": "2026-10-09T04:00:00.000Z",
  "boardId": "waveshare-esp32-s3-eth",
  "boardSettings": { "camera": "unknown" },
  "components": [
    {
      "id": "led-1",
      "moduleId": "clex.hardware.led",
      "moduleVersion": "1.0.0",
      "name": "Внешний светодиод 1",
      "parameters": { "resistorOhms": 330, "forwardVoltage": 2 }
    }
  ],
  "gpioAssignments": [
    { "componentId": "led-1", "terminalId": "anode", "pinId": "P34", "gpio": 17, "mode": "output" }
  ],
  "logic": {
    "nodes": [], "edges": [], "viewport": { "x": 0, "y": 0, "zoom": 1 }
  },
  "assembly": {
    "positions": { "board": { "x": 100, "y": 40 }, "led-1": { "x": 670, "y": 100 } },
    "viewport": { "x": 0, "y": 0, "zoom": 1 },
    "connections": [
      { "id": "wire-1", "componentId": "led-1", "terminalId": "anode", "boardPinId": "P34" },
      { "id": "wire-2", "componentId": "led-1", "terminalId": "cathode", "boardPinId": "P28" }
    ]
  },
  "moduleVersions": { "clex.hardware.led": "1.0.0" }
}
```

Названия проектов и компонентов: 1-80 символов, описание до 4000. ID проекта – UUID. ID элементов – стабильные безопасные ключи. Даты записываются в ISO 8601 UTC.

`boardId` ссылается на общую библиотеку плат. `components` содержит до 100 экземпляров, их точные версии и параметры. Исходники модулей в JSON не копируются. `moduleVersions` должен совпадать с версиями экземпляров. Неподдерживаемая установленной библиотекой версия сохраняется в данных без подмены и отображается как ошибка совместимости.

Физическое соединение связывает контакт компонента с контактом платы либо другого компонента. Допускается до 200 соединений; приемный контакт не повторяется в нескольких связях. `gpioAssignments` – синхронизированное производное представление сигнальных связей для генератора. GND и питание не записываются как логические сигналы. Рассинхронизация импортированных назначений с соединениями отображается как ошибка.

Соединение с контактом платы использует `boardPinId`. Для провода между компонентами вместо него указываются `sourceComponentId` и `sourceTerminalId`; приемная сторона задается прежними `componentId` и `terminalId`. Эти варианты взаимоисключающие. Соединения обмоток двигателя с драйвером сохраняются в этом формате и не создают назначения GPIO.

Необязательное `assembly.connections[].route` содержит 1-32 промежуточные точки `{x, y}` ручного маршрута с числовыми координатами в диапазоне -50000-50000. Концы вычисляются по контактам. При перемещении устройства редактор обновляет прилегающие изгибы и сохраняет новые точки вместе с положением устройства; внутренние ручные участки сохраняются. При одинаковом смещении платы и компонента весь маршрут переносится вместе с ними. Коллинеарные возвраты к старым позициям удаляются. Отсутствие поля означает автоматический маршрут. Сброс удаляет поле. Геометрия сохраняется без повышения версии формата и не влияет на GPIO или прошивку.

`assembly.positions.board` содержит положение платы; остальные ключи совпадают с ID компонентов. Сохраняются панорама и масштаб 0.2-3. Незавершённый/ошибочный по электрическим правилам проект можно сохранить как черновик. Файлы с неправильной структурой, дубликатами ID/контактов, осиротевшими связями или невалидными координатами отклоняются до записи.

Граф `logic` содержит до 100 блоков и 300 типизированных связей. Его структура описана ниже. Дополнительные неизвестные поля сохраняются при round-trip.

## Совместимость с форматом 1

Сохранённые проекты этапа 1 читаются как прежде. Чистая пустая схема формата 1 преобразуется **в памяти**: сохраняются ID, название, описание и даты; `boardId` остаётся `esp32-s3-generic`; добавляются настройки и положение монтажа. Чтение не переписывает файл. При следующем ручном или вызванном изменением графа автоматическом сохранении записывается формат 3.

Новые проекты сразу создаются в формате 3. Для ESP32-S3-ETH исходное состояние камеры – `unknown`. Приложения этапов 1/2 формат 3 не открывают, что предотвращает потерю аппаратной схемы старой версией.

Внешний импорт по-прежнему создаёт независимую копию с новым ID. Экспорт сохраняет текущую форму, в том числе несохранённые правки. Отдельных миграционных файлов или изменений чужих проектов нет.

## Узлы и связи логики

```json
{
  "nodes": [
    { "id": "timer-1", "moduleId": "clex.logic.timer", "moduleVersion": "1.0.0", "name": "Таймер 1", "position": { "x": 60, "y": 100 }, "parameters": { "intervalMs": 500 } },
    { "id": "toggle-1", "moduleId": "clex.logic.gpio-toggle", "moduleVersion": "1.0.0", "name": "Переключение GPIO 1", "position": { "x": 390, "y": 100 }, "parameters": { "componentId": "led-1" } }
  ],
  "edges": [
    { "id": "edge-1", "source": "timer-1", "sourceHandle": "tick", "target": "toggle-1", "targetHandle": "trigger", "dataType": "event" }
  ],
  "viewport": { "x": 0, "y": 0, "zoom": 1 }
}
```

Это содержимое `logic`; карта `moduleVersions` при таком графе дополнительно содержит `clex.logic.timer` и `clex.logic.gpio-toggle` версии `1.0.0`. Типы связей: `event`, `boolean`, `number`, `text`. ID узлов и связей уникальны, оба конца существуют, у каждого входа одна связь. Семантические ошибки схемы отображаются отдельно от валидации структуры. Runtime-поля React Flow, функции, измерения DOM и выделение не сериализуются. История и буфер копирования не сохраняются.

Формат 2 с корректным монтажом и пустой логикой обновляется до 3 в памяти без изменения компонентов, GPIO, позиций, настроек камеры и версий аппаратных модулей. Формат 2 с непустым графом отклоняется как неподдерживаемый исходный файл.

Изменение графа включает отложенное сохранение всего проекта; простое открытие/чтение не записывает миграцию. Неизвестные дополнительные поля остаются в данных; использованные версии модулей синхронизируются с аппаратными компонентами и логическими узлами.

## Стороны контактов и интерфейсы экранов

Необязательное `assembly.portSides` хранит `{componentId: {terminalId: "left" | "right" | "top" | "bottom"}}`. Это только расположение точки; ID соединений и GPIO остаются прежними. Без поля используется расположение из описания модуля.

Необязательное `screens` хранит интерфейсы по ID аппаратного компонента. Каждый экран содержит `formatVersion: 1`, `background` и `elements`. Текстовый элемент содержит стабильный `id`, `type: "text"`, Unicode `text`, целочисленные `x`/`y`, `fontId` и HEX-цвет `color`. Размеры и допустимые глифы берутся из описания дисплея.

Логический блок экрана хранит только `parameters.componentId`. При удалении аппаратного устройства его интерфейс и стороны контактов очищаются; оставшийся логический блок показывает ошибку привязки. Старые проекты без этих необязательных полей читаются без миграции файла.

Динамический текст задаётся необязательным `mode: "dynamic"` и полями `name`, `valueType: "number" | "boolean" | "text"`, `initialValue`, `prefix`, `suffix`. Отсутствующий `mode` означает статический текст; старые экраны сохраняют поведение. Источник значения хранится только в `logic.edges` с `targetHandle` равным стабильному ID элемента. Общее событие обновления использует `targetHandle: "trigger"`; для отдельных элементов доступны `targetHandle: "update.<elementId>"`. Идентификаторы портов допускают до 200 символов, идентификаторы самих элементов – до 100.


Индикатор имеет `type: "indicator"` и тот же стабильный `id`, координаты и `fontId`. Размеры и оформление задают `width`, `height`, `radius`, `padding`, `gap`, `dotVisible`, `dotSize`, `dotPosition` и `align`. Массив `states` содержит `{id, name, value, text, background, color, dotColor}`; `staticStateId` и `fallbackStateId` выбирают статическое и резервное состояния. Для динамического состояния используются `mode`, `valueType` и `initialValue`. Необязательная динамическая надпись включается `captionDynamic`, начальный текст хранится в `initialCaption`.

Состояние подключается обычной связью к `targetHandle: "<elementId>"`, надпись – к `"caption.<elementId>"`. Отдельные события обновления используют `"update.<elementId>"` и `"update.caption.<elementId>"`. Состояния и подписи не создают отдельную систему передачи данных. `editStateId` существует только в черновике редактора и не сохраняется.

Для P4 `boardSettings.chipRevision` хранит `pre-v3` либо `v3`; настройки физического подключения `audio`, `mipiDisplay`, `mipiCamera` используют `unknown`, `connected`, `disconnected`. DSI, аудио и камера хранят `parameters.interfaceId`, который ссылается на встроенный интерфейс платы; логические блоки хранят обычный `componentId`. Данные кадров и состояние аудио в проект не записываются.

Сетевой аппаратный компонент хранит `providerId` и `addressMode`; для SPI-интерфейса используется выбранный `spiHost`, для RMII он не применяется; статический IPv4 дополнительно использует `staticIp`, `netmask`, `gateway`, `dns`. Реальные IP-адреса и результаты HTTP являются данными времени выполнения и не записываются в проект. Логический Ethernet хранит ссылку `componentId` на аппаратный экземпляр. Проверка ресурса хранит `url`, `method`, `intervalMs`, `timeoutMs`.

## Папка хранения

В десктопной версии каталог выбирается через **Настройки → Хранилище проектов → Выбрать папку**. Путь относится к настройкам приложения и не включается в JSON проекта. При смене каталога текущие правки сохраняются, JSON-файлы копируются с проверкой содержимого, исходные файлы остаются резервной копией. Разные файлы с одинаковым именем не перезаписываются. Формат проекта и идентификаторы не меняются. После переключения новые записи и удаления относятся к выбранной папке.
