# Сенсорная кнопка

Универсальный аппаратный компонент `clex.hardware.touch-button` версии **1.0.0** для емкостных модулей с готовым цифровым выходом. Производитель и микросхема не определяют генерацию. Встроенные сенсорные площадки ESP32 без внешнего цифрового модуля сюда не относятся.

## Подключение

Добавьте **Сенсорную кнопку** в «Монтаже»:

- **VCC** – питание 3,3 или 5 В, выбранное по документации конкретного модуля. Подключение к другому напряжению платы отклоняется.
- **GND** – общая земля.
- **OUT** – свободный цифровой вход GPIO.

В свойствах укажите фактическое напряжение HIGH на OUT. Напряжение питания модуля и допустимый уровень GPIO – разные характеристики. Для ESP32 проверка отклоняет OUT выше 3,3 В. Питание 5 В допустимо при прямом подключении к ESP32 только для модуля, который действительно обеспечивает выход 3,3 В; выбор значения в программе не понижает физическое напряжение. Для модуля с выходом 5 В нужен внешний согласователь уровней, который текущий компонент отдельно не моделирует. Комбинация OUT выше VCC отклоняется.

Поддерживаемые варианты питания не означают, что любой сенсорный модуль допускает оба напряжения. Сверьте характеристики своего изделия. Например, официальный каталог [Tontek](https://www.tontek.com.tw/product/product2?idx=243&lang=) указывает диапазон питания TTP223-BA6 2,0-5,5 В; характеристики готовой платы могут отличаться. Допустимые уровни ESP32 приведены в [даташите Espressif](https://www.espressif.com/sites/default/files/documentation/esp32-s3_datasheet_en.pdf).

## Логика

Используются существующие блоки:

- **Изменение входа** – после выбора сенсорной кнопки называется «События сенсора». Выходы: «Сенсор активирован», «Сенсор деактивирован», «Состояние сенсора изменилось», «Сенсор активен?».
- **Считать вход** – после выбора сенсора называется «Проверить сенсор». По входному сигналу выдает текущее состояние.

Активный уровень **HIGH/LOW** задается в свойствах компонента в «Монтаже». Состояние Да означает, что OUT соответствует выбранному активному уровню. События активации и деактивации сохраняют этот смысл при обоих вариантах. Число миллисекунд задает фильтр устойчивого изменения; 0 отключает задержку. Начальное состояние запоминается без ложного события активации, удержание не создает повторных событий. При переключаемом выходе сенсорного модуля событие соответствует изменению OUT, а не каждому физическому касанию.

Пример: «Сенсор активирован» → вход «Прибавить 1» счетчика. Таймер для наблюдения за изменениями не нужен.

## Реализация и проверки

Новых логических блоков и отдельного драйвера сенсорной микросхемы нет. Переиспользуются опрос цифрового входа, фильтр, блоки чтения/изменения и GPIO-генерация ESP-IDF/Arduino AVR. Для сенсора внутренняя подтяжка отключена. Для механической кнопки сохранились подтяжка вверх, прежние названия, полярность и фильтр; ее каталог и драйвер событий не изменены. Сгенерированные файлы существующих сценариев механической кнопки на S3, P4 и Nano совпали с сохраненными до изменений.

Общие расширения каталога: `terminal.voltageParameter` получает напряжение питания из свойства компонента; `constraints.signalVoltageParameter` / `supplyVoltageParameter` позволяют проверять уровни OUT и VCC. Прежнее фиксированное `terminal.voltage` продолжает работать. Чтение GPIO выбирает компонент по возможности цифрового входа, а не по идентификатору механической кнопки.

Проверены HIGH/LOW, VCC/GND/OUT, несовместимые напряжения, сохранение/открытие и интерфейс. Программное исполнение сгенерированного Arduino AVR-кода проверяет фильтрацию импульсов, одиночное событие при удержании, деактивацию, счетчик и чтение состояния. Генерация ESP32-S3 и ESP32-P4 проверена программными тестами. Реальное подключение сенсора и прошивка платы в этой задаче не выполнялись.

Проверки: `npm test`, `npm run lint`, `npm run test:nano-runtime`, `npm run test:touch-button-ui`. Локальные журналы и снимки: `.artifacts/touch-button/`.
