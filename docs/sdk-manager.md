# Инструменты разработки

SDK Manager использует одну систему хранения, обнаружения и активации в установленном приложении и `npm run tauri dev`. Для текущих профилей ESP32-S3 требуется **ESP-IDF 5.4.4**; выбор другого SDK пока не расширяет совместимость генератора.

## Существующие установки

При запуске читаются сохранённые записи CLEX Flow, реестры EIM, переменные процесса и стандартные каталоги SDK. Каждая установка отображается отдельно с версией, путём и состоянием. Выбранное окружение проходит проверку Python, версии ESP-IDF, Xtensa GCC, CMake и Ninja.

В «Настройки → Инструменты разработки» можно повторить поиск, подключить существующий каталог и выбрать активную установку для ESP32-S3. SDK используется по исходному пути, не копируется в CLEX Flow и не переустанавливается. Удаление внешних установок отсутствует в интерфейсе и запрещено системным слоем.

Пути, каталог доступных версий, результаты проверки и активный выбор сохраняются в `sdk-manager.json` системного каталога настроек. Удалённый или перемещённый SDK отображается недоступным. Кэшированные сведения не заменяют повторную проверку активного окружения при запуске.

## Установка через EIM

Если нужного SDK нет, выберите «Установить нужный SDK» либо конкретную версию каталога. До запуска отображается оценка загрузки по официальным размерам инструментов и требуется подтверждение полной загрузки. Системные зависимости разрешаются отдельным переключателем.

Используется официальный Espressif Installation Manager с проверкой поддерживаемых CLI-параметров. Если EIM отсутствует, загружается CLI **0.20.0** для macOS ARM64/x64 или Windows x64 из официального GitHub Release. SHA-256 архивов/EXE закреплены по опубликованным digest. Несовпадение запрещает запуск. SDK и инструменты не включаются в установщик приложения.

Новые SDK находятся в локальном каталоге данных приложения:

```text
<app-local-data>/sdks/esp-idf/v<version>/
  .clex-sdk.json       Маркер владельца
  v<version>/esp-idf/  Исходники SDK
  tools/              Компиляторы и Python-окружения
  registry/           Отдельный eim_idf.json
  activation/         Скрипты EIM
  installation.log    Диагностика установки
```

Каждая версия имеет собственный каталог инструментов и реестр EIM. Настройки глобального EIM не используются для записи. Телеметрия EIM выключена. Вызовы установщика принимают только фиксированные параметры backend; команд из проектов или модулей нет.

Интерфейс показывает этапы, реальный вывод EIM, ошибки и отмену. Для bootstrap-файла EIM доступны счётчик байтов и процент; для SDK отображается вывод самого установщика, без выдуманного общего процента. После EIM обязательно проверяются инструменты и собирается отдельный тестовый проект ESP32-S3. Только затем SDK получает статус «Проверен» и становится активным.

## Ошибки и повтор

Сбой сети, неполный файл, неправильная SHA, ошибка EIM, отсутствие зависимостей или неудачная компиляция не считаются успешной установкой. Прерванная запись сохраняется как прерванная/неполная; доступна повторная установка. Перед началом проверяется минимум 8 ГиБ свободного места. Общий фактический объём зависит от выбранной версии и зависимостей.

На macOS недостающие системные зависимости могут требовать Homebrew и Command Line Tools. CLEX Flow не устанавливает Homebrew самостоятельно и не запрашивает административные права автоматически. Если EIM не может удовлетворить зависимости, установка останавливается с диагностикой. На Windows используются механизмы установки prerequisites EIM. Разрешение этих действий относится только к явному подтверждению пользователя в диалоге.

## Активация и сборка

PATH и переменные ESP-IDF формируются для дочерних процессов автоматически. Активация не требует терминала. Параметры устанавливаются в окружении процесса, не в глобальном PATH пользователя. Файл состояния деактивации IDF перенаправлен в собственный кэш CLEX Flow, чтобы не менять состояние терминала VS Code.

EIM и стандартная ESP-IDF имеют разные размещения tools/constraints; они учитываются при поиске окружения. Для ESP32-S3 используется отфильтрованный tools-манифест в кэше приложения, без изменения исходного `tools.json`. Portable Git EIM и кодировки Python на Windows учитываются отдельно.

Смена SDK, Python или набора инструментов изменяет идентификатор окружения. Существующая система сборки/прошивки проверяет его и блокирует запись прежней сборки. Параллельные операции SDK, компиляции, прошивки и монитора запрещены внутри экземпляра приложения.

## Удаление

Удаляются только SDK с действующим маркером владельца CLEX Flow и ожидаемым каталогом версии. Требуется подтверждение. Символические ссылки/reparse points на корне управляемого SDK не допускаются; вложенные ссылки удаляются как ссылки. Пользовательские установки не удаляются. После удаления активной версии нужно выбрать другую или установить SDK заново.

## Платформы и проверки

Реализованы пути, процессы, загрузки EIM и serial-порты для macOS Apple Silicon, macOS Intel и Windows x64. На macOS ARM64 проверены реальное обнаружение/активация существующей ESP-IDF, сборка Blink, сохранение выбора между dev-режимом и `.app`, а также защита внешних установок. Для установки проверены небольшие файлы, checksum/error/cancel и имитации ответов; **полная установка нового SDK и чистая система пока не испытаны**. Выполнять такую проверку следует отдельно после согласования объёма загрузки.

В GitHub Actions прошли unit-тесты и сборки `.dmg` для macOS ARM64/Intel и `.exe` NSIS для Windows x64. Работа SDK Manager с физическими устройствами на Windows и macOS Intel требует отдельной проверки. Удаление настоящего пользовательского SDK не тестируется.

Другие платформы – Arduino, ESP8266, STM32, RP2040/RP2350 – не устанавливаются текущим механизмом. Их можно добавить через новые требования платформы и системный обработчик SDK без изменения редактора или основного процесса сборки ESP-IDF.
