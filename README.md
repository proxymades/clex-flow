# CLEX Flow

**CLEX Flow – Visual Microcontroller Studio**, версия **0.1.0**. **Work in Progress:** активная разработка; стабильного релиза пока нет. Независимое локальное десктопное приложение для небольших цифровых экспериментов с микроконтроллерами. Технологии: Tauri 2, Rust для файлов/процессов, React 19 + JavaScript/JSX, Vite, React Flow, CSS, Lucide, JSON/SVG и ESP-IDF. Интерфейс на русском, основной проверенный компьютер – macOS Apple Silicon.

Реализованы **этапы 1-4: проекты, аппаратный монтаж, визуальная логика и интеграция ESP-IDF**. Можно собрать фиксированную схему в настоящий ESP-IDF-проект, получить `.bin`, выбрать подключённый порт, записать прошивку с подтверждением и открыть Serial. Сборка из нативного приложения проверена на macOS; прошивка физической платы, Serial реального устройства и мигание LED ещё не проверены.

Номер **0.1.0** согласован как номер первой версии приложения. Номера 1, 2, 3 и 4 обозначают этапы разработки. Первый планируемый официальный релиз – **v0.1.0, Pre-release**; тег и Release будут созданы отдельно после проверки.

## Микроконтроллеры и границы проверки

Генератор нацелен на **ESP32-S3 / ESP-IDF 5.4.4**. В каталоге есть профили Waveshare ESP32-S3-ETH и Espressif ESP32-S3-DevKitC-1 v1.1 N8R8. Другие варианты MCU не реализованы. Профили основаны на документации производителей, но физическая прошивка этих плат, GPIO и Serial устройства ещё не испытаны; ревизия ESP32-S3-ETH не подтверждена. Это не заявление о проверенной аппаратной совместимости.

## Запуск

Нужны Node.js 22.12+ (или поддерживаемая Vite версия Node.js), npm, Rust stable и Xcode Command Line Tools. На проверенном компьютере доступны Node.js 22.21.1, Rust 1.93.1 и Xcode. Для редакторов ESP-IDF не нужен; для сборки требуется существующая установка ESP-IDF 5.4.4 и её инструменты.

```sh
git clone https://github.com/proxymades/clex-flow.git
cd clex-flow
npm ci
npm run desktop
```

Первый запуск Cargo может загрузить зависимости. Системные требования Tauri для других ОС описаны в [официальной документации](https://v2.tauri.app/start/prerequisites/).

Собрать приложение:

```sh
npm run desktop:build
```

На macOS результат находится в `src-tauri/target/release/bundle/macos/CLEX Flow.app`. Конфигурация пока создаёт `.app`; установщики для Windows/Linux ещё не настроены. Разработка использует совместимые Tauri Rust 2.10.x и JS API 2.10.1; зафиксированные зависимости лежат в `package-lock.json` и `src-tauri/Cargo.lock`.

Уже проверенная отладочная сборка находится в `src-tauri/target/debug/bundle/macos/CLEX Flow.app`. Откройте её через Finder. Для повторной отладочной сборки:

```sh
npm run tauri -- build --debug
```

Веб-предпросмотр интерфейса:

```sh
npm run dev
```

Адрес: `http://127.0.0.1:1420`. В браузере данные хранятся в localStorage, в десктопном приложении – в JSON-файлах. Эти хранилища независимы. Очистка данных браузера удалит проекты предпросмотра; экспортируйте нужные проекты в JSON.

## Что работает

- Главный экран, список последних проектов и поиск по названию.
- Создание проекта с названием, описанием и конкретной платой ESP32-S3; основной профиль ESP32-S3-ETH.
- Открытие проекта из библиотеки; открытие внешнего JSON как независимой локальной копии с новым ID.
- Переименование, редактирование описания, сохранение и экспорт JSON.
- Удаление локального проекта с явным подтверждением. Корзины и восстановления пока нет.
- Атомарная замена файла при сохранении: временный файл создаётся в том же каталоге, синхронизируется и заменяет прежний.
- Проверка JSON, версии формата, ID, полей и размера до 2 МБ. Повреждённые проекты не стираются; ошибки отображаются отдельно.
- Защита несохранённых изменений при переходе, закрытии окна Tauri, выходе через меню/⌘Q и обновлении страницы браузера.
- Сохранение через `⌘ + S` / `Ctrl + S`.
- Рабочее окно с изменяемой шириной боковых панелей и высотой нижней панели. Разделители поддерживают мышь и стрелки клавиатуры.
- Диалоги с управлением фокусом, Escape и удержанием Tab внутри диалога.
- Локальные шрифты, SVG-изображения и значок приложения; интерфейс не загружает внешние ресурсы.
- Вкладка «Монтаж»: плата с подписанными физическими контактами, LED с резистором и кнопка, поиск и категории.
- Выбор контактов на холсте или через свойства, плавные провода, перемещение, панорама и масштаб.
- Проверка зарезервированных GPIO, конфликтов, направлений, питания, общих контактов камеры, параметров и версий модулей.
- Сохранение монтажа и графа в формате 3; чтение форматов 1/2 без автоматической перезаписи.
- Пять логических блоков: таймер, чтение GPIO, установка GPIO, переключение GPIO, сообщение в Serial.
- Четыре типа портов, запрет несовместимых/повторных связей и циклов, проверка связи с монтажом.
- Выделение, копирование со связями, удаление, Undo/Redo и автосохранение изменений графа через 800 мс.
- Детерминированная генерация C, CMake и sdkconfig из проверенной схемы; просмотр четырёх исходных файлов.
- Поиск существующей ESP-IDF 5.4.4, настройка путей, проверка Python, GCC, CMake и Ninja.
- Настоящая сборка, stdout/stderr, остановка дерева процесса, отдельный каталог кэша приложения.
- Список USB/Serial-портов и обновление списка. Запись только актуальной успешной сборки в выбранный порт с подтверждением; контроль SHA-256 файлов.
- Serial 115200 бод, отключение монитора, сохранение UTF-8 между чтениями; вывод не требует перевода строки.
- Блокировка редактирования/выхода во время операций, одна операция ESP-IDF одновременно.

## Монтаж ESP32-S3-ETH

1. Создайте проект и выберите ESP32-S3-ETH; откройте «Монтаж».
2. Добавьте внешний светодиод. Нажмите «Анод через R» на карточке, затем GPIO17 (контакт P34). Катод соедините с GND (например P28).
3. По умолчанию задан резистор 330 Ом. Он должен действительно находиться в цепи; приложение не проверяет физический резистор.
4. Для кнопки нажмите плату на холсте и в свойствах укажите «Камера отключена» только после проверки. Добавьте кнопку: сигнал на GPIO16 (P32), общий на GND.
5. Проверяйте ошибки в нижней панели. Сохраните через кнопку или ⌘/Ctrl + S.

Колесо мыши изменяет масштаб, фон перемещает холст, плата и карточки перетаскиваются. Через свойства можно заменить GPIO, отключить провод или удалить компонент. «Показать весь монтаж» вписывает схему. Для назначения допустим и обратный порядок: контакт платы, затем контакт компонента.

Ревизия вашей ESP32-S3-ETH не определена. Источники профиля доступны в свойствах платы и документации. SVG сохраняет порядок выводов, но не является механическим чертежом. Проверка схемы не подтверждает реальную разводку, питание или работу устройства.

## Логика

Откройте «Логика», добавьте таймер 500 мс и переключение GPIO, выберите подключённый LED и соедините «Такт» → «Выполнить». Дождитесь отметки автосохранения. [Подробные правила и клавиши](docs/logic.md).

Автосохранение после изменения графа записывает весь текущий проект, включая другие правки. Undo/Redo работает для графа, не для монтажа. Генерация и сборка доступны. Проверка реального Blink остаётся отдельным этапом 5.

## Сборка и подключение

1. В «Настройки» дождитесь автопроверки ESP-IDF 5.4.4 или укажите существующие SDK и Python. Никакая установка автоматически не выполняется.
2. Создайте корректный монтаж и граф. Нажмите значок исходников и проверьте сформированные файлы.
3. Нажмите «Собрать». Нижняя панель показывает настоящий вывод ESP-IDF; успешная сборка выводит путь к `.bin`. «Остановить» завершает принадлежащие приложению процессы.
4. Подключите плату и нажмите «Обновить порты». Выберите соответствующий USB-порт; системные Bluetooth/debug-порты исключены.
5. Убедитесь в модели и физическом монтаже. «Прошить» открывает подтверждение перед заменой программы платы. После изменения схемы или режима консоли требуется новая сборка.
6. Откройте монитор значком справа, скорость 115200 бод. Перед новой сборкой или прошивкой остановите монитор.

По умолчанию консоль USB Serial/JTAG; для подключения через USB-UART выберите UART0 в настройках и пересоберите. [Подробная инструкция и ограничения](docs/esp-idf.md). Последовательный монитор только принимает данные, не предоставляет командную оболочку или IDF GDB-функции.


## Где находятся проекты

Tauri определяет системный каталог данных приложения. На macOS:

```text
~/Library/Application Support/kz.clex.flow/projects/<UUID>.json
```

Точный путь виден в «Настройки». Имя файла основано на ID, а не на пользовательском названии; переименование проекта не меняет путь. Открытие внешнего файла создаёт локальную копию и не меняет исходный файл. Повторное открытие создаёт ещё одну копию. Экспорт сохраняет текущую версию формы, в том числе ещё не сохранённые локально правки, и не снимает отметку несохранённых изменений.

## Проверки

```sh
npm run lint
npm test
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --manifest-path src-tauri/Cargo.toml
```

Повторяемая проверка UI в отдельном временном браузерном профиле (не затрагивает пользовательские проекты):

```sh
npx playwright install chromium
# В одном терминале: npm run dev
# В другом:
npm run test:ui
npm run test:assembly-ui
npm run test:logic-ui
npm run test:firmware-ui
```

Если Chromium уже установлен в другом месте, укажите переменную `CLEX_BROWSER_EXECUTABLE`. Результаты экспорта и снимки интерфейса сохраняются в `.artifacts/`, этот каталог исключён из Git. Playwright используется только для проверки и не входит в десктопную поставку.

Проверены 49 JS-тестов, 9 Rust-тестов, четыре browser-сценария, нативная сборка/отмена и две реальные конфигурации firmware через ESP-IDF. Тесты и компиляция не подтверждают работу оборудования.

## GitHub и будущие релизы

Исходники: [proxymades/clex-flow](https://github.com/proxymades/clex-flow). Разработка ведётся в `main`. Номера технических этапов не образуют версий приложения. Перед релизом версии в npm, Tauri и Cargo должны совпадать; проверка: `node scripts/check-version.mjs`.

Workflow **Build macOS Apple Silicon** запускается только вручную либо после явной публикации GitHub Release. Обычные коммиты/теги не запускают сборку. Используется официальный механизм Tauri, target `aarch64-apple-darwin`, отдельная release-конфигурация и выходной `.dmg`. Workflow сохраняет артефакты для тестирования; не создаёт теги/Release и не прикрепляет непроверенные файлы к Release.

Порядок тестирования, подпись/нотариализация и ручное прикрепление `.dmg`: [docs/releases.md](docs/releases.md). Первый планируемый релиз `CLEX Flow v0.1.0` должен быть **Pre-release**. Сейчас он не создан.
